    13. The storage stack, layer by layer¶

    Depth: L2 · Reading time: ~7 min · Last verified: 2026-11-01 Prerequisites: What storage does · Inside an SSD · Block protocols and NVMe-oF · File protocols · Datacenter networking

    TL;DR¶

    • Every I/O crosses eight layers: application, file system or object API, volume manager, protocol, network, array software, SSD controller/FTL, media. Architectures differ in which layer holds the "intelligence": placement, protection, reduction and metadata.
    • Storage history is that intelligence moving: from the host (DAS), into a shared networked box (SAN and NAS, 1990s), across commodity server clusters (2000s), then into stateless compute over shared flash (late 2010s on).
    • Each layer crossed costs latency; each layer owned earns margin. A 4 KB database write takes ~20–40 µs on a local SSD and ~100–250 µs on a networked array. The extra microseconds buy shared, protected, reduced data.
    • Everpure owns three adjacent layers. Purity array software also does the FTL's job on raw NAND inside DirectFlash modules. Most rivals stop at array software; software-only vendors stop higher.
    • Vertical integration is a bet, not a default. It buys density, efficiency and a separately licensable layer (the hyperscaler wins), at the cost of more R&D and NAND supply exposure.

    Why this matters for Everpure strategy¶

    Part 3 compares architectures: dual-controller arrays, shared-nothing clusters, DASE, parallel file systems, object stores and HCI. Each is best read as an answer to one question: which layer does the clever work, and on whose hardware? That question maps onto the business. Owners of a scarce layer set prices; assemblers of commodity layers compete on cost. Everpure (NYSE: P, formerly PSTG) reported a 70.4% GAAP gross margin for fiscal 20261; Supermicro, which builds servers largely from bought-in parts, reported 11.1% for fiscal 20252.

    The stack is also a map of adjacencies. Everpure's hyperscaler wins license the bottom layers (DirectFlash modules and flash management) without the array software, on hardware the customer sources34. WEKA attacks from the top, selling software for partners' servers5.

    Core concepts¶

    Eight layers, one I/O¶

    Read the stack top to bottom as the path of a write:

    1. Application. A database, hypervisor or training job decides what must be durable, and when (for a database, at commit).
    2. File system or object API. Turns names (/db/redo01.log, a bucket and key) into blocks or objects and keeps the namespace, which is metadata (Chapter 21).
    3. Volume manager. Pools and remaps block addresses: LVM, software RAID, a hypervisor's storage layer.
    4. Protocol. SCSI or NVMe for blocks, NFS or SMB for files, S3 for objects (Chapters 7–9).
    5. Network. Fibre Channel, Ethernet or InfiniBand; in DAS, a PCIe slot (Chapter 10).
    6. Array controller software. Purity, ONTAP, VAST and the like: placement, RAID or erasure coding, snapshots, replication, reduction.
    7. SSD controller and FTL. Maps logical blocks to NAND pages, levels wear, collects garbage (Chapter 3).
    8. Media. NAND, storage-class memory or disk (Chapter 2).

    Figure 13.1 — Every architecture has the same layers; what differs is which row holds the intelligence, and Everpure is unusual in owning rows 6 through 8 as one design.

    "Intelligence" means four jobs: placing, protecting, shrinking and tracking data. Where an architecture puts them decides what its network carries and where it hits its scaling wall.

    Semiconductor bridge: the compute stack. Computing runs from application to compiler to ISA to microarchitecture to memory controller to DRAM cells, and profit follows layer ownership. NVIDIA owns CUDA, the compiler and the silicon, and posted a 71.1% GAAP gross margin in fiscal 20266; a server assembler owning none of those layers earns about a sixth of that. In storage the FTL plays the memory controller's role: address mapping and wear management that hide media physics behind a clean interface. Whoever owns it decides how much raw NAND capability reaches the customer, and at what DRAM and spare-capacity cost. (Layers are not the whole margin story; R&D intensity and scale matter too.)

    Tracing one 4 KB database write¶

    flowchart TD
    A["1 Database commit: 4 KB log write + fsync<br/>~1–5 µs"] --> B["2 File system and block layer in kernel<br/>~5–20 µs"]
    B --> C["3 Volume manager remaps address<br/>~1 µs"]
    C --> D["4 NVMe-oF initiator builds command<br/>RDMA ~5–15 µs, TCP ~20–35 µs adder"]
    D --> E["5 NIC and 2–3 switch hops<br/>~1–5 µs"]
    E --> F["6 Array software: map, hash, persist<br/>to mirrored or shared NVRAM ~30–100 µs"]
    F --> G["ACK back up the stack<br/>end to end ~100–250 µs"]
    F -.-> H["7 Later: array or FTL writes full stripe<br/>off the critical path"]
    H -.-> I["8 NAND program: TLC hundreds of µs,<br/>QLC longer"]
    J["DAS comparison: local NVMe SSD acks<br/>from protected DRAM, ~20–40 µs total"]

    Figure 13.2 — Illustrative, order-of-magnitude latencies: on a networked array the network, protocol and controller software dominate a small write, and NAND programming is hidden behind NVRAM.

    Walk the numbers. A networked array acknowledges the write once it sits in two NVRAM locations (mirrored to the partner controller, or in NVRAM modules both controllers can reach, as on FlashArray; see Chapter 14), not when it reaches NAND. The critical-path steps sum to roughly 45–165 µs one way; with the return trip and queueing, a 4 KB write lands near 100–250 µs, consistent with the 150 µs quoted for FlashArray//XL170 (company-stated, conditions unspecified)7. A local NVMe SSD skips layers 4–6 and acknowledges from power-loss-protected DRAM.

    Three lessons follow. NAND is not on the write critical path: NVRAM or SSD DRAM absorbs the write and the slow program happens later. Network and software dominate small-I/O latency, which is why transport matters for databases: NVMe-oF over RDMA adds about 5–15 µs over local NVMe8, NVMe/TCP roughly 20–35 µs in early tests9, and the host kernel path becomes a large share of latency on very fast SSDs10. The extra ~100 µs buys what DAS lacks: one copy shared by many hosts, surviving controller loss, deduplicated, snapshotted and replicated.

    How Everpure approaches it vs. competitors¶

    Player Layers owned Hardware model Strategic implication
    Everpure FlashArray / FlashBlade 6, 7 and module design for 8 (Purity + DirectFlash); buys NAND Own controllers and modules Density and efficiency gains; NAND supply exposure
    Everpure hyperscaler deals 7 and module design (DirectFlash, flash management) Customer sources hardware; Everpure does not procure the NAND4 A layer sold on its own, without the array
    IBM FlashSystem 6 and 7 (own FlashCore Modules) Own modules with on-module compression11 The closest integrated rival
    Dell, NetApp arrays 6 Standard third-party SSDs (Dell contrast noted by TechTarget11) Multi-source drives; adopt each SSD generation quickly
    VAST 6, plus enclosure designs Commodity SSDs; servers via Supermicro, HPE, Cisco12 Software margin on partner hardware
    WEKA, Ceph, Nutanix 6 (or 3 in HCI) Software on commodity servers51314 Ride server cost curves; no hardware inventory
    AWS All eight Own Nitro SSDs with a rewritten FTL15 Proof that the largest buyers can build layer 7 themselves

    Table 13.2 — Everpure and IBM integrate down to the flash; most rivals stop at array software, and software-only players stop above the hardware entirely.

    Why collapse layers 6 and 7? A standard SSD's FTL works blind: it does not know which blocks the array will soon overwrite, so it may copy dead-to-be data during garbage collection, and it carries its own spare area and DRAM. With DirectFlash, Purity drives raw NAND and handles placement, garbage collection and wear levelling across all modules at once16. The DRAM arithmetic matters as drives grow: a 4-byte map entry per 4 KB page is 1 TB ÷ 4 KB × 4 B ≈ 1 GB of DRAM per TB, or ~150 GB for a 150 TB drive. Folding mapping into array software, which already keeps metadata for deduplication and snapshots, lets module capacity scale without that DRAM bill. DFMs went from 75 TB in 2023 to 150 TB, with 300 TB reported in August 20261718 [VERIFY: official 300 TB DFM GA date].

    Steelman the alternatives. Software-only vendors ride server and SSD cost curves for free, run in any cloud and focus R&D on one layer. Array vendors on standard SSDs multi-source drives and adopt each SSD generation once qualified, while Everpure must engineer modules for each NAND generation and carries supply risk: it raised prices in February 2026 as NAND costs surged19. AWS's Nitro SSD, claimed at 60% lower latency than OEM drives, proves hyperscalers can build layer 7 themselves15. The licensing thesis therefore rests on staying ahead in time-to-capacity, not on the layer being unreplicable.

    Options a strategy team might evaluate, based on public information: how far to license layers 7 and 8; whether FlashBlade//EXA's third-party data nodes (Chapter 16) dilute the integration thesis or extend Purity's reach; and which layer becomes contestable as DPUs absorb storage services.

    Each move answered a bottleneck: stranded DAS capacity, then controller limits, then (with flash) the network and software themselves. Two signals point to the next re-cut.     Conversation playbook¶

    Questions for a PM

    1. "In hyperscaler deals, which layer are we monetizing, and what stops the customer building it?" Strong: flash management and module design; AWS Nitro proves in-sourcing is possible; the moat is time-to-capacity per NAND generation and exabyte-scale qualification.
    2. "When a customer insists on software-only, what do we offer and what do we give up?" Strong: names the cases (sovereign cloud, standard server fleets, public cloud), the products that serve them, and the density lost off DirectFlash.
    3. "In latency-driven deals, which layer is the bottleneck?" Strong: host stack, transport and controller software, with NVMe/TCP versus RDMA numbers; not NAND.

    Questions for an engineer

    1. "Walk a 4 KB write: where is the persistence point, and what is each layer's p99 contribution?" Strong: names the NVRAM mirror point, per-layer microseconds, and which layer degrades first under load.
    2. "What does Purity know that a drive FTL cannot, and what does that do to write amplification at 90% full?" Strong: a quantified write-amplification or over-provisioning comparison plus the mechanism.
    3. "If Flexible Data Placement lets any array steer placement on standard SSDs, what DirectFlash advantage remains?" Strong: separates what FDP closes (placement) from what it does not (DRAM, density, power, global wear management).

    Don't say this:

    • "Flash latency is the bottleneck." On networked arrays, network and software dominate small writes; NAND programming is off the critical path.
    • "DirectFlash is an SSD without the case." It removes the drive-level FTL; flash management moves into Purity.
    • "Software-defined means no hardware." Someone's hardware always runs it; the question is who carries inventory and earns margin.
    • "SAN and NAS are different hardware." They differ mainly in who owns the file system: host or array.
    • "Disaggregation is new." Every era re-cut the stack.

    Key terms¶

    • Storage stack — the eight layers from application to media.
    • Data services ("intelligence") — placement, protection, reduction, metadata.
    • Persistence point — where a write becomes safe to acknowledge.
    • Vertical integration — owning adjacent layers, e.g. array software, FTL and module.
