    19. Software-defined storage and HCI¶

    Depth: L2 · Reading time: ~7 min · Last verified: 2026-11-01 Prerequisites: Scale-up dual-controller arrays · Scale-out shared-nothing clusters · Block protocols and NVMe-oF · Data protection and resilience

    TL;DR¶

    • Software-defined storage (SDS) sells the storage OS without the box (Ceph, MinIO, VAST, WEKA). Hyperconverged infrastructure (HCI) runs it on the same nodes as the VMs (Nutanix, vSAN).
    • HCI's wall is coupled scaling. Every node adds compute and capacity in a fixed ratio, stranding whatever the estate did not need.
    • Cloud block storage is SDS at hyperscale. EBS replicates volumes inside one Availability Zone, with a separate configuration service and Nitro-card offload.
    • Broadcom's VMware licensing reset (from December 2023) reopened "HCI vs. array" and pushed customers toward Nutanix, public cloud and external arrays.
    • Software-only buys margin %, no NAND inventory and fast iteration; appliances buy gross profit per deal and control of the media.

    Why this matters for Everpure strategy¶

    Everpure (NYSE: P, formerly PSTG) mostly sells appliances built on its own DirectFlash modules. Yet it already runs every other model here: Portworx (Kubernetes SDS), Purity on cloud instances, and a Meta DirectFlash technology licence with no Everpure hardware1.

    Broadcom forces the choice: every VMware renewal must stay on vSAN, switch HCI stacks, or split compute from storage. Everpure's May 2025 Nutanix partnership, with FlashArray as external storage for the AHV hypervisor, is a bet on the third2.

    Core concepts¶

    Three ways to package the same software¶

    Figure 19.1 — The software is similar in all three; what changes is who supplies hardware and what must scale together.

    In the appliance model (Chapter 14) one vendor designs, qualifies, ships and supports the whole box. SDS runs on commodity servers from a hardware compatibility list (HCL), usually as a shared-nothing cluster. HCI folds storage into the hypervisor cluster: each node gives CPU and memory to a storage service (Nutanix's controller VM, or vSAN inside the ESXi kernel) that replicates each VM's writes to other nodes' drives.

    Semiconductor bridge. An appliance vendor is an IDM: it owns design and integration, carries inventory and captures integration margin. A software-only vendor is an IP licensor like Arm, collecting a high-margin fee on hardware others build. VAST's "Gemini" model is fabless: VAST specifies the hardware, a manufacturing partner sells it to the customer at cost, and VAST books only software3.

    Where HCI hits the wall¶

    State and metadata. Data sits on node-local drives (replication factor 2–3, or erasure coding across nodes); metadata is distributed across the cluster. A node is at once compute host, storage target and metadata participant, so losing it touches all three.

    Worked example: stranded resources. An illustrative node has 64 cores and 8 × 15.36 TB SSDs (123 TB raw, ~61 TB usable at RF2). An estate needs 400 cores and 2 PB usable. Sized for compute, ⌈400 ÷ 64⌉ = 7 nodes give only ~430 TB. Sized for capacity, ⌈2,000 ÷ 61⌉ = 33 nodes give 2,112 cores, 81% idle. Under per-core subscriptions such as VMware Cloud Foundation (VCF), idle cores still need licences; VCF's bundled 1 TiB of vSAN per licensed core4 softens this without fixing it. The fix is un-converging: Nutanix storage-only and compute-only nodes; vSAN Max (2023), a storage-only cluster of up to 8.6 PB that other clusters mount5; or an external array behind HCI compute2. Each concedes HCI's one-building-block promise.

    Two more walls follow. East-west amplification: at RF2 every write crosses the cluster network again, and rebuilding a failed 123 TB node at ~5 GB/s of spare bandwidth takes 123,000 ÷ 5 ≈ 6.8 hours. Noisy neighbours: busy VMs starve their node's storage service.

    Failure HCI (Nutanix / vSAN-style) EBS-style cloud block
    Drive Rebuild that drive's data from replicas on other nodes; VMs keep running Invisible to tenant; storage fleet re-replicates
    Node VMs restart elsewhere (hypervisor HA) and its data re-replicates; two recoveries at once Storage server loss: chain reconfigured, new replica re-mirrored; brief I/O pause
    Storage controller CVM or kernel module failure: I/O redirected to another node's storage service Nitro card failure is a host failure; volume can attach to a new instance
    Network link / partition Minority side loses quorum; a split cluster can halt writes Chain cannot complete writes until configuration service picks a new replica set6

    Table 19.1 — HCI couples application and data recovery on the same nodes; cloud block moves that complexity into a control plane.

    Inside an EBS-style cloud block service¶

    From AWS's public papers and docs: an EBS volume lives in one Availability Zone, replicated across several servers there7. On Nitro instances the guest sees an ordinary NVMe device8, emulated by a Nitro card that turns block commands into network requests. Classic EBS keeps each volume on a replication chain (client → primary → replica). A separate configuration master, Physalia, records chain membership in a seven-node Paxos "cell" per volume, so one failure cannot strand many volumes' configuration6. The io2 Block Express back end talks to Nitro over Scalable Reliable Datagram (SRD)9, a multipath transport in the Nitro card that sprays packets across many network paths10.

    flowchart LR
    VM["Guest VM: NVMe driver"] --> NC["Nitro card: NVMe emulation, encryption, SRD"]
    NC --> NET["AZ network: multipath"]
    NET --> P["Storage server: primary"]
    P --> R["Storage server: replica"]
    P -.-> CM["Configuration master: Physalia cells"]
    R -.-> CM
    NC -.-> CM
    P --> S3["Snapshots to S3, multi-AZ"]

    Figure 19.2 — The configuration master sits off the data path and matters only when a chain changes.

    Figure 19.3 — A write is acknowledged only after both chain copies persist it; network round trips, not flash, dominate latency.

    sequenceDiagram

    participant N as Nitro card
    participant P as Chain member

    N->>P: read request over SRD

    N-->>G: decrypted data and completion
    Note over N,C: Only if a member fails
    N->>C: who owns this volume now
    C-->>N: new chain membership

    Figure 19.4 — Reads need one copy; the configuration master must survive partitions, when membership changes.

    Block Express internals are public only at a high level, so the read diagram leaves the serving copy generic. AWS rates io2 Block Express at 256,000 IOPS, 4,000 MB/s and 64 TiB per volume, under 500 µs average for 16 KiB I/O, and 99.999% durability9. The fleet-level lesson came in April 2011: a network change cut many volumes off from their replicas, all re-mirrored at once, and the "re-mirroring storm" exhausted the zone's spare capacity11. It is the HCI rebuild problem at cloud scale: rate-limit repair and reserve capacity, or recovery becomes the outage.

    Table 19.3 — Software-only maximizes margin percentage and iteration speed; appliances maximize gross profit per deal and media control.

    Worked example (illustrative split). On a US$1M system, an appliance vendor books US$1M at 66%: US$660k gross profit. A software-only vendor might book US$400k at 88%: US$352k, with the OEM taking US$600k of hardware. In exchange it carries no inventory or NAND risk and ships on new CPUs immediately. Open source caps pricing from below; a free tier that is good enough must be fenced, as MinIO did with AGPLv3 in 202117, a stripped community console in 202518 and maintenance mode in December 202519.

    How Everpure approaches it vs. competitors¶

    Everpure's centre of gravity is the appliance, justified by DirectFlash's density and power advantage over commodity SSDs (Chapter 26). At the edges it runs software-only motions: Portworx, container-native SDS bought for about US$370M in 202020; Purity on cloud infrastructure16; off-the-shelf FlashBlade//EXA data nodes (Chapter 16); and the Meta technology licence1.

    Steelman the alternatives: Nutanix runs ~88% gross margins on US$2.55B ARR growing 16%12; VAST scales on OEM supply chains without inventory3; IBM's 2022 absorption of Red Hat's Ceph team21 keeps "free and good enough" alive. The appliance reply: HCL support is costly and AI-era power limits reward co-designed media. Options a strategy team might evaluate, based on public information: more "array behind someone else's HCI" partnerships; DirectFlash licensing as a repeatable IP business; and Portworx against VMware for VMs moving to Kubernetes.

    Figure 19.5 — SDS and HCI matured quietly; Broadcom's 2023 licensing reset made platform choice a board-level cost decision.

    Broadcom closed VMware on 22 November 2023, then ended perpetual licences and folded thousands of SKUs into two bundles, VCF and vSphere Foundation22. AT&T's 2024 lawsuit cited a proposed 1,050% increase; it later settled23. Much of the base paid: Broadcom reported ~US$27B of FY2025 infrastructure-software revenue24 [VERIFY: FY2025 infrastructure-software total, transcript summaries only], and in June 2025 its CEO said over 87% of its 10,000 largest customers had adopted VCF25.

    Storage felt it. Gartner expects over a third of VMware workloads to move by 202826. Nutanix's FlashArray integration reached GA around the turn of 2026227. It was not Nutanix's first external storage: Dell PowerFlex took that slot in May 2025, and Dell PowerStore followed in 202628. VCF 9 deprecated vVols, the main external-array hook, with removal planned for 9.12930. The trajectory is un-convergence: split node types, arrays behind HCI, Kubernetes-native SDS for VMs. Cloud block storage has been SDS since EBS was built in 200831.

    Conversation playbook¶

    Questions for a PM

    1. "In a VMware renewal, when do we win behind Nutanix rather than against vSAN?" Strong: capacity-heavy estates, stranded-core licence cost, data reduction; concedes edge and small clusters to HCI.
    2. "What is our gross profit per deal, not margin %, against a software-only rival?" Strong: splits software and hardware dollars and NAND risk.
    3. "What breaks first if Purity ships as software on customer-chosen servers?" Strong: HCL support cost, lost DirectFlash density, Evergreen economics.

    Questions for an engineer

    1. "What happens to a database VM's p99 latency during an HCI node rebuild?" Strong: rebuild bandwidth caps, throttling policy, time to full redundancy.
    2. "How does a cloud block service avoid a re-mirroring storm?" Strong: reserved spare capacity, rate-limited repair, a small-blast-radius configuration service.
    3. "What does NVMe/TCP to an external array cost versus local HCI reads?" Strong: tens of microseconds, offset by avoided replica writes.

    Don't say this:

    • "HCI is just SDS." It is SDS sharing nodes with applications; that coupling is its defining weakness.
    • "Software-only is always better economics." Higher percentage, smaller revenue base, support shifted to the HCL.
    • "EBS is a SAN in the cloud." It is a replicated service with a separate configuration plane, scoped to one zone.
    • "Broadcom killed vSAN." VCF bundles vSAN capacity, so many customers now own more of it.
    • "Ceph is free." The software is; people, testing and hardware qualification are not.

    Key terms¶

    • SDS — storage software sold apart from its hardware.
    • HCI — compute, storage software and media in every node.
    • Stranded resources — capacity or compute bought only because the node bundles it.
    • Chain replication — writes flow along an ordered server chain; a configuration master tracks membership.
