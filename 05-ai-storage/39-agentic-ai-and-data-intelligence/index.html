    39. Agentic AI and data intelligence¶

    Depth: L2 · Reading time: ~9 min · Last verified: 2026-11-01 Prerequisites: Metadata · Control planes · Platform and software · The AI data pipeline end to end · RAG, vector databases and AI-native data formats

    TL;DR¶

    • Agents turn metadata into a product. An agent can only use data it can find, interpret and is allowed to touch, so knowing what exists, what it means and who may use it becomes as valuable as the bytes.
    • MCP is becoming the agent's I/O bus. The Model Context Protocol (open-sourced November 2024, given to a Linux Foundation fund in December 2025, >10,000 servers) standardises how agents call tools1. Bulk data still moves over S3, NFS and SQL.
    • Agents change the access pattern. An agent fans one question out into dozens of tool calls and hundreds of small reads, each needing a delegated permission decision and a log line.
    • Every storage vendor now claims this layer. VAST, NetApp, Dell, Hammerspace, Cohesity and Everpure (Data Intelligence, from the US$125.0M 1touch deal2) all pitch it, against far larger catalog and data-security vendors.
    • The strategic question is neutrality. Storage vendors see every write; data and security vendors see every vendor's storage and own the buyer. A storage vendor wins only if it covers data not on its own arrays.

    Why this matters for Everpure strategy¶

    Everpure's "Data Primacy" pitch and its 1touch purchase rest on one bet: in an agentic enterprise, the scarce asset is trusted context about data, not capacity. If agents become the main consumers of data, control moves to whoever answers three questions per request: what is this, may this agent see it, and what did it do with it. A vendor that answers them stays sticky as hardware commoditises; one that does not becomes the S3 endpoint under someone else's catalog (Chapter 33).

    The rivals are not only storage vendors. Salesforce paid US$8 billion for Informatica's catalog and governance business (closed November 2025)3. The data-security posture management (DSPM) specialist Cyera raised US$600 million at a US$12 billion valuation in June 2026, up from US$6 billion a year earlier (reported)4. Those prices show where the value sits, and how costly it is to buy in.

    Core concepts¶

    Metadata is the raw material¶

    A storage system holds three kinds of metadata, and owns two of them by default (Chapter 21):

    1. System metadata: names, paths, sizes, owners, access-control lists (ACLs), timestamps, snapshots, replicas.
    2. Telemetry: who read or wrote what, when, from where. Control planes such as Pure1 log it (Chapter 22).
    3. Content-derived metadata: what the bytes are. This file holds a passport number; this table is EU customer data. Producing it means opening and classifying content, the job of discovery and DSPM tools and now Everpure Data Intelligence.

    Semiconductor bridge: system metadata is the tag RAM of a cache: it tells you a line exists and where. Content metadata means reading the data array itself, which costs bandwidth. Telemetry is the on-die bus monitor: only something on the write path sees every transaction without sampling, the core of the storage-vendor argument (Chapter 28).

    Catalogs and semantic layers¶

    A catalog records what datasets exist, their schemas, owners, classifications and lineage. A semantic layer records what business terms mean: one governed definition of "active customer" or "net revenue", with the joins and filters that compute it. Humans carry these definitions in their heads; agents do not. Ask an LLM for "Q3 churn" over 4,000 raw tables and it guesses a join, returning a confident wrong number.

    The industry is standardising this layer. Snowflake's Open Semantic Interchange (OSI) published a first, Apache-2-licensed specification in January 2026 covering datasets, metrics, dimensions and relationships. Salesforce, dbt Labs, Collibra, Atlan, Alation and dozens of others were in the working group, and Databricks joined at the January update5. Snowflake calls v1 a starting point and plans foundation-led governance. An analyst noted Everpure is not a member6 [VERIFY: search-summary only]. Semiconductor bridge: the semantic layer is the instruction-set architecture between "software" (agents) and "hardware" (tables and files), and whoever writes the ISA shapes everything above it.

    MCP: the agent's I/O bus¶

    MCP defines how an AI application (the host, with an MCP client) discovers and calls an MCP server that exposes tools (actions), resources (readable data) and prompts. Messages are JSON-RPC7. MCP replaces an M × N mesh of custom connectors8: a storage vendor writes one server and every compliant agent can use it.

    MCP is a control and query plane, not a data plane: an agent asking for "contracts with change-of-control clauses" gets references and snippets; training-scale bytes still move over S3, NFS or GPUDirect (Chapter 11). It also pushes security onto the server. The 2025-11-25 specification treats MCP servers as OAuth resource servers, forbids passing the client's token through to upstream APIs, and warns of confused-deputy attacks, in which a server with broad privileges is tricked into acting for a caller who lacks them9. An MCP server in front of an array is a privileged deputy by design.

    Why agents create new access patterns¶

    Figure 39.2 — The policy check and audit write sit on the critical path of every agent tool call.

    An agent splits a task into parallel sub-queries, retries and chains tools. Four properties follow.

    • Many small reads. Metadata lookups and 4–64 KB chunk fetches dominate, favouring low-latency flash and fast metadata services over raw GB/s.
    • Fan-out. Like a GPU warp's scatter-gather loads, the slowest of hundreds of object touches sets completion time.
    • Fine-grained, delegated permissions. The agent acts on behalf of a user, so the effective right is the user's entitlements intersected with the agent's scope, often at row or field level, finer than array ACLs.
    • Lineage. Auditing or undoing an action requires knowing which object versions informed it; snapshots make that possible.

    Worked example (illustrative). 5,000 employees each give an agent 10 tasks a day; each task makes 8 tool calls touching 25 objects. That is 5,000 × 10 × 8 × 25 = 10 million access decisions a day. Over a 10-hour workday that averages 10M ÷ 36,000 s ≈ 280 per second, with peaks several times higher. The same humans opening ~50 files each make 250,000, 40× fewer. At ~1 KB per log record, that is ~10 GB of audit log a day, or ~1.8 TB over six months. Databricks says agents created ~80% of databases on Neon (company-stated, 2025)10.

    Semiconductor bridge: the policy engine is to agents what an IOMMU is to DMA-capable devices. Every access is translated and permission-checked, and the decision cache works like an IOTLB. Too slow and every I/O stalls; cache too long and a revoked permission stays live.

    Governance becomes a runtime requirement¶

    The EU AI Act (Regulation 2024/1689) entered into force on 1 August 2024. Its prohibitions applied from 2 February 2025 and general-purpose AI model obligations from 2 August 202511. For high-risk systems, defined by use case (hiring, credit, critical infrastructure), not by whether an agent is involved, Article 10 requires governed, representative training data and Article 12 automatic event logging, with logs kept at least six months11. The Digital Omnibus on AI (Regulation 2026/1744, published 24 July 2026, in force 27 July 2026) moved high-risk deadlines to 2 December 2027 (Annex III) and 2 August 2028 (embedded in regulated products). It did not delay prohibitions, GPAI rules or the Article 50 transparency duties, which applied from 2 August 20261213. Fines reach €35 million or 7% of worldwide turnover for prohibited practices11.

    Gartner predicted in June 2025 that over 40% of agentic AI projects would be cancelled by the end of 2027, citing cost, unclear value and weak risk controls14: governance decides whether agents reach production.

    Can storage vendors own this layer?¶

    The storage-vendor case: the array holds the inventory and sits on the write path, so it can classify on ingest or from snapshots without weekly crawls. It can enforce policy where the bytes live, and immutable snapshots can undo what an agent did.

    The data and security-vendor case: data sits on many vendors' storage, in SaaS and in cloud, so one vendor's governance is partial; the buyer (CDO or CISO) is not the storage buyer; and catalog and DSPM vendors are neutral and already wired to identity systems. Coverage of other people's data decides it, which is why NetApp's September 2026 move to index any NFS, SMB or S3 store15 and Dell's claim that its orchestration engine works beyond Dell storage16 matter more than their feature lists.

    Trade-offs. VAST is the steelman for "storage becomes the AI data platform": database, runtime and policy in one system, but scoped to data on VAST. NetApp has the deepest metadata heritage and now indexes rival storage. Dell (Dataloop) and Everpure (1touch) each bought a ~US$120–125M startup to get here. Cohesity and Rubrik hold a full copy of most enterprise data and can undo agent actions. Everpure's asset is entity-level classification plus a Pure1-managed fleet (Chapter 28); its gap is proof on non-Everpure data.

    Options a strategy team might evaluate, based on public information:

    1. Neutral metadata hub. Price Data Intelligence separately, lead with non-Everpure estates, connect to Unity Catalog, Polaris and Purview, and join OSI.
    2. Best substrate, partner above. Feed write-path events and snapshot-based scanning to DSPM and catalog vendors.
    3. Agent-safety primitives. Package SafeMode snapshots, per-agent QoS and audit export as "agent undo".
    4. Tuck-in M&A. Semantic-layer or lineage assets in the 1touch price range. DSPM leaders at Cyera-type valuations are out of reach.

    Conversation playbook¶

    Questions for a PM

    1. "What share of Data Intelligence bookings cover data not on Everpure?" Strong: a number and named estates (Oracle, M365, rival NAS).
    2. "Who is the buyer: storage admin, CDO or CISO, and who carries the quota?" Strong: a named persona, separate SKU and quota credit for non-array deals.
    3. "How does Data Intelligence coexist with a customer's Purview, Collibra or Cyera?" Strong: it feeds them, no rip-out.

    Questions for an engineer

    1. "What does the MCP server do with a user's identity: pass it through, exchange it, or use a service account?" Strong: token exchange, per-agent scopes, no shared superuser.
    2. "How many policy decisions per second can you sustain, and how fast does a revocation take effect?" Strong: measured rates, cache lifetime in seconds, fan-out behaviour.
    3. "Is classification on the write path or off it?" Strong: off-path, snapshot- or event-triggered, bounded controller impact.

    Don't say this:

    • "MCP moves the data." It moves requests and results; bulk bytes use S3, NFS or SQL.
    • "The EU AI Act regulates all agents as high-risk." Risk class depends on use case.
    • "Array ACLs are enough for agents." They work at file or share level; agents need delegated, field-level decisions.
    • "Storage vendors will displace Databricks or Snowflake." The realistic prize is the metadata and policy beneath them.
    • "Data intelligence is just RAG." RAG retrieves; data intelligence decides what may be retrieved.

    Going deeper (optional, L3 pointers)¶

    • MCP specification 2025-11-25: authorization and security sections (OAuth 2.1, RFC 8707, RFC 9728).
    • EU AI Act Articles 10, 12, 19 and 26, and the Digital Omnibus amendments to Article 113.
    • The OSI specification; Unity Catalog's access-control model.
    • Google's Zanzibar (USENIX ATC 2019) for high-rate permission checks.
