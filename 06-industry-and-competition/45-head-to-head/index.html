    45. Head-to-head: FlashBlade//EXA vs. VAST vs. WEKA vs. DDN¶

    Depth: L2 · Reading time: ~12 min · Last verified: 2026-11-01 Prerequisites: Disaggregated shared-everything · Parallel file systems · FlashArray and FlashBlade · Reading benchmarks · VAST · WEKA · DDN

    TL;DR¶

    • All four split metadata from data, but in different places. EXA runs metadata on a Purity core and sends bulk data straight to data nodes over pNFS. VAST keeps every byte and all metadata on shared SCM and QLC behind stateless CNodes. WEKA hashes metadata into buckets on every node. DDN puts Lustre metadata on an MDS and data on OSS appliances, and runs a second key-value engine, Infinia, beside it.
    • No vendor wins every deal. VAST leads where buyers want a multi-tenant, multiprotocol platform with references at 10,000+ GPUs. DDN leads where Lustre heritage, NVIDIA's own designs and sovereign procurement decide. WEKA leads where storage must follow the GPUs into clouds or into the GPU servers themselves. EXA leads on peer-reviewed throughput, standard clients and existing Everpure relationships.
    • EXA's evidence is strong but narrow. It posted the top MLPerf Storage v3.0 checkpoint-write and KV-cache-read results in September 2026, in a round VAST, WEKA and DDN all skipped.
    • EXA is behind on references, badges, cloud reach and data-node maturity. No public 10,000-GPU EXA reference exists. NVIDIA's SuperPOD and NCP badges belong to FlashBlade//S, not EXA. No public-cloud EXA exists, and data-node reduction and protection run on a young release train.
    • The features are converging, so the next fight is over proof and economics. Every vendor is an NVIDIA STX partner, every one sells or has announced a KV-cache tier, and WEKA and DDN are adding the data reduction VAST built its business on. What separates vendors in 2027 is reference scale, $/TB under NAND inflation, and operations.

    Why this matters for Everpure strategy¶

    FlashBlade//EXA is Everpure's entry ticket to the GPU-cluster market that VAST, WEKA and DDN built (Chapter 41). The three rivals each won that market a different way, so a single "EXA vs. competitors" pitch fails. The architecture that beats Lustre on operations is not the one that beats VAST on platform breadth or WEKA on portability. A strategy team needs a map of which deals EXA should chase, which it should concede, and which gaps in product, certification or commercial terms change the odds.

    This chapter is that map. It reuses the deep dives' facts (Chapters 27, 42, 43, 44) and adds a common frame: one diagram, one matrix, one scoring chart and a deal-by-deal verdict. Chapter 49 widens the lens to the whole field.

    Core concepts¶

    Four architectures in one picture¶

    Every scale-out file system has to answer three questions. Where does the namespace (the metadata) live? How many network hops does a byte take from flash to GPU? What has to be installed on the client? The four vendors answer them differently.

    Figure 45.1 — EXA and DDN send bulk data one hop, straight to where it lives. VAST adds a CNode hop in exchange for shared, stateless compute. WEKA does away with the metadata server by spreading metadata across every node.

    FlashBlade//EXA is a parallel file system built on a standard protocol. The metadata core is FlashBlade hardware running Purity//FB on DirectFlash blades. Launch materials described one to ten chassis of ten blades each1. Data nodes are third-party Linux servers with NVMe SSDs running Purity//DN. Clients fetch a file's layout over NFSv4.1 on TCP, then read and write data nodes directly over RDMA2. Chapter 16 explains why this is a metadata/data split rather than DASE.

    VAST is the DASE reference design. Stateless CNodes run every protocol and data service. All state, metadata included, sits on DBoxes: about 1% SCM and about 99% QLC, reached over NVMe-oF34. Any CNode can serve any request.

    WEKA NeuralMesh is shared-nothing. Every backend node runs the same user-space processes. Metadata is split into thousands of buckets spread across all nodes, and a hash of each operation picks the bucket that owns it5. The fast path needs WEKA's client driver and DPDK kernel bypass6.

    DDN sells two engines. EXAScaler is Lustre: an MDS hands out layouts, and clients stream stripes to OSS appliances over RDMA. Infinia is a separate key-value platform built on a Bε-tree, serving S3, KV-cache and limited POSIX access78. The DDN CORE control plane spans both9.

    Semiconductor bridge. Read the four as memory-system topologies. EXA and Lustre resemble a directory-based design: one lookup in a directory (the metadata server), then a direct transfer from the bank that holds the line. VAST is uniform memory access through a crossbar: every core is one hop from every bank, and the crossbar is always on the path. WEKA resembles address-interleaved channels with distributed tag ownership. There is no central directory, and the cost appears when one operation spans many owners.

    Five differences that decide deals¶

    1. The data path and the client. EXA and Lustre move bulk data one hop. VAST takes two, and its write path multiplies back-end traffic. A 1 GB/s client write lands in SCM on two DBoxes (2 GB/s), is read back for migration (1 GB/s) and is written to QLC as a wide stripe (about 1.03 GB/s), so the fabric carries about 4 GB/s (Chapter 16). VAST pays that tax for stateless compute and global reduction. The client choice runs the other way. EXA and VAST use the stock NFS client, while WEKA and Lustre need a kernel module qualified against every GPU-server image. A neocloud that rebuilds images weekly counts that as an operating cost, not a footnote.

    2. Where metadata lives. At thousands of GPUs, metadata is usually the bottleneck, not bandwidth (Chapter 21). EXA's bet is a dedicated, scale-out Purity metadata tier. VAST's is metadata in shared SCM, so it scales with DBoxes but costs a fabric round trip per lookup. WEKA's is hashing, which avoids hot spots but turns a cross-directory rename into a distributed transaction. Lustre's is an MDS that is sharded by hand (DNE) when one target saturates. No public benchmark compares the four on, say, a billion-file listing, so the strongest metadata claim belongs to whoever runs the buyer's proof of concept.

    3. Capacity economics. Protection overhead compounds at scale. For 50 PB usable: VAST at 146+4 needs 50 ÷ 0.973 ≈ 51.4 PB raw; WEKA at 16+4 or a Lustre OST at 8+2 RAID needs 50 ÷ 0.8 = 62.5 PB. That is about 11 PB of raw flash between them before any data reduction. With NAND contract prices still rising (TrendForce forecast a further 15–20% for 4Q26)47, this is where VAST's design pays. EXA's data-node protection and reduction figures are not public. That is the single most important number for Everpure to publish.

    4. KV cache. All four now sell, or have announced, a shared KV-cache tier (Chapter 32). WEKA shipped first: AMG became commercially available in November 202529, and in June 2026 a joint OCI test grew the cache from 8.64 TiB of DRAM to 287 TiB of NVMe (vendor-run)48. EXA has the only peer-reviewed number: 1,623.4 GiB/s of KV-cache read on 51 hosts21. To put that in tokens: a 70B model's 128K-token context is about 42 GB in FP16 (Chapter 43). 1,623.4 GiB/s ≈ 1,743 GB/s, so the system could reload about 41 such contexts per second (1,743 ÷ 42). But PureKVA itself was only announced on 30 September 2026, with availability slated for October26. NVIDIA's STX reference architecture now names all four as partners45, which turns the KV tier into a standard slot and shortens any lead.

    5. Proof. Each vendor proves itself differently. DDN points to NVIDIA's own clusters (Eos used 48 AI400X2s for about 4 TB/s19). VAST points to CoreWeave's US$1.17B agreement (reported by Reuters)49. WEKA points to portability and SPECstorage. EXA points to peer-reviewed benchmarks. Chapter 37 explains why "absence is data" cuts both ways. Rivals skipping MLPerf v3.0 means EXA's first place came against a thin field, and a buyer running a 10,000-GPU proof of concept may trust a reference call over a leaderboard.

    Worked example: one checkpoint, two kinds of number. Take a 405B-parameter model with Adam optimizer state, about 6.5 TB (Chapter 31). EXA's peer-reviewed 877.5 GiB/s is about 942 GB/s from 30 data nodes, so a synchronous save takes 6.5 ÷ 0.942 ≈ 6.9 seconds, or about 31 GB/s per data node. Eight DDN AI400X3 appliances at a reseller-listed 110 GB/s write each give about 880 GB/s, or 7.4 seconds (Chapter 44). The two times look equivalent, but they are different kinds of number. EXA's is a measured, peer-reviewed system result. DDN's is a sum of datasheet figures, though DDN's Eos install delivered about 93% of its summed datasheets. Neither tells a buyer the cost per usable TB or per kilowatt, which is the comparison that actually decides the purchase. A strategy team should insist that every competitive claim says which kind of number it is.

    Table 45.2 — Everpure is the likely winner in one archetype of six, runner-up in two more and a credible challenger in a third. The pattern says EXA's growth depends on converting the enterprise base and on closing the neocloud reference gap.

    The neocloud row deserves a closer look, because it is the largest pool of spend. Neoclouds rarely single-source. CoreWeave, VAST's largest customer, also lists WEKA and Everpure among its dedicated-storage options52, and Everpure holds an equity stake in it43. EXA's realistic entry is therefore a second-source tier, won on per-rack throughput, power and data-node sourcing. The aim is a named reference by 2027, not displacing VAST at CoreWeave.

    The table is a base rate, not a forecast. Specific deals flip on price, supply and timing. In a NAND shortage, a vendor that can guarantee delivery of media it designs may beat a cheaper software licence on hardware the buyer cannot source (Chapter 48). That favours Everpure's DFM supply chain only once data nodes use DFMs.

    How Everpure approaches it vs. competitors¶

    Everpure's pitch is a parallel-file-system data path without the parallel-file-system client, backed by Purity metadata, Evergreen ownership and peer-reviewed numbers. Each rival has a credible counter.

    Steelman VAST. Breadth compounds. One Element Store serves files, objects, tables, block and Kafka streams. Every new engine reuses the same data without copies, and the fleet of neoclouds running it is the largest in the category. VAST's company-stated committed ARR above US$500M and a US$30B valuation53 give it currency to outspend everyone on field engineering.

    Steelman WEKA. It is the only one that follows the GPUs anywhere: on-premises, inside GPU servers, in four clouds, and next onto DPUs. Its KV-cache product, commercially available since November 2025, has the longest sales record of the four: about seven months ahead of DDN's Dynamo-integrated release and nearly a year ahead of PureKVA.

    Steelman DDN. NVIDIA runs its own supercomputers on DDN. Lustre's coherent shared-file writes and open code suit labs and governments, and a profitable, founder-owned supplier passes procurement tests venture-backed rivals sometimes fail. Blackstone's US$300M at a US$5B valuation54 and a reported revenue doubling toward about US$1B in 2026 (reported by Forbes)55 show momentum.

    Conversation playbook¶

    Questions for a PM

    1. "Which of the six deal archetypes produced our last ten EXA wins and losses?" A strong answer maps wins and losses to archetypes, names the decisive factor in each, and admits where EXA should not compete. Consolidation deals, for example, belong to FlashBlade//S.
    2. "What is EXA's effective $/TB against VAST at 50 PB, including protection and reduction on the data nodes?" A strong answer gives measured ratios, the stripe geometry and the NAND cost assumption. It does not quote VAST's marketing median back at them.
    3. "When does EXA get its own NCP and SuperPOD badges, and which deals are we losing until then?" A strong answer gives a level, a GPU generation and a quarter, and names the deals.

    Questions for an engineer

    1. "Under a rename storm or a billion-file listing, how does the Purity metadata core compare with WEKA buckets and a DNE-sharded Lustre MDS?" A strong answer cites test data, separates throughput from tail latency, and explains where each design serialises.
    2. "What does EXA give up against a Lustre client on N-to-1 shared-file writes?" A strong answer separates file-per-rank checkpoints from shared files, covers pNFS layout recall, and quantifies the per-client GB/s.
    3. "With STX, what in our KV-cache path is still ours?" A strong answer separates NVIDIA's interfaces (Dynamo, NIXL, BlueField-4) from Everpure's own software: metadata scale, tenancy and placement.

    Don't say this:

    • "EXA beat VAST, WEKA and DDN in MLPerf." They did not enter v3.0.
    • "FlashBlade//EXA is SuperPOD-certified." The public record shows FlashBlade//S, not EXA.
    • "VAST is a hardware company" or "WEKA is an appliance vendor." Both earn mostly software revenue on partner hardware, even though WEKA now sells WEKApod appliances.
    • "DDN is legacy Lustre." It runs NVIDIA's clusters, sells Lustre as a Google service and ships a second, newer engine.
    • "Everyone has KV cache, so it's a wash." Maturity, evidence and Dynamo integration differ by up to a year.

    Key terms¶

    • Metadata/data split — a design that keeps the namespace on a dedicated tier and moves bulk data directly between clients and data servers.
    • Bulk-data hop — one network traversal a data byte makes between flash and the client.
    • Purity//DN — the software running on FlashBlade//EXA data nodes.
    • Deal archetype — a recurring buyer profile whose binding constraint decides the vendor choice.
    • Binding constraint — the single requirement that eliminates most options in a deal.
    • Evergreen//One for AI — Everpure's storage-as-a-service offering for AI, extended to FlashBlade//EXA in 2026.
    • See the glossary for the rest.
