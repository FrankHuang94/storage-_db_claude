    Numbers and symbols¶

    • 3-2-1-1-0 rule — Backup guideline of three copies, two media, one off-site, one immutable or offline, and zero restore-verification errors. (Ch 6)

    A¶

    • Accelerator utilisation (AU) — the share of time a simulated accelerator spends computing rather than waiting for data; MLPerf Storage results must stay above a threshold. (Ch 37)
    • Acknowledgement point — the moment a storage system tells the host that a write is durable. (Ch 56)
    • Active recall — Producing an answer from memory before checking it, rather than rereading the material. (Ch 59)
    • Active/non-optimized path — A working path that costs an extra internal hop and is used only when optimized paths fail. (Ch 14)
    • Active/optimized path — A path the array advertises as the preferred, lowest-latency route to a volume. (Ch 14)
    • Active/passive — A controller arrangement in which one controller serves all I/O while the other waits to take over. (Ch 14)
    • Adam optimizer — The standard optimizer for large models, which stores a running mean (first moment) and running variance (second moment) of each parameter's gradient. (Ch 31)
    • AFR (annualized failure rate) — The fraction of devices expected to fail per year of operation. (Ch 20)
    • AFX — NetApp's disaggregated all-flash ONTAP system in which controllers share NVMe enclosures over a fabric. (Ch 46)
    • Agent rollback — Undoing changes an AI agent made to files, databases or configurations, typically by restoring from snapshots or backups. (Ch 39)
    • Agentic AI — AI systems that plan and carry out multi-step tasks by calling tools and data sources, not just answering a single prompt. (Ch 39)
    • Agentic operations — Infrastructure management in which AI agents diagnose and, within limits, act on systems rather than only advise. (Ch 53)
    • AGPLv3 — A copyleft open-source licence that requires sharing source code even when software is offered over a network. (Ch 19)
    • AHV — Nutanix's hypervisor, the main destination for many VMware migrations. (Ch 47)
    • AI agent — An LLM-driven program that plans and executes multi-step tasks by calling tools, APIs and data sources. (Ch 30)
    • AI Data Engine (AIDE) — NetApp's ONTAP extension that indexes, vectorises and governs data for AI pipelines. (Ch 46)
    • AI data pipeline — The end-to-end flow of data through ingest, curation, training, checkpointing, fine-tuning, inference, RAG and agents, each with its own storage I/O pattern. (Ch 30)
    • AI factory — NVIDIA's term for a data centre whose GPUs, networks, storage and software are designed as one production line whose output is AI tokens. (Ch 35)
    • AI infrastructure tracker (IDC) — IDC's quarterly measure of server and storage spending deployed for AI workloads. (Ch 40)
    • AI momentum — The atlas's composite of 2025–26 evidence of AI-driven growth: revenue, bookings, valuation, design wins, benchmarks and shipping AI features. (Ch 49)
    • AI-native depth — How much of the AI data path a vendor serves on architecture it owns and designed for AI workloads. (Ch 49)
    • AI-native storage vendor — A storage company whose growth and roadmap centre on GPU-cluster workloads, such as VAST Data, WEKA and DDN. (Ch 41)
    • AI-Q blueprint — NVIDIA's reference agent workflow that uses NeMo Retriever microservices to search enterprise data. (Ch 34)
    • AI400X series — DDN's 2U all-NVMe EXAScaler appliances (AI400X, AI400X2, AI400X3, AI400X3M), each generation raising bandwidth per box. (Ch 44)
    • AIOps — Use of analytics and machine learning on infrastructure telemetry to predict faults, open tickets and recommend or take corrective actions. (Ch 22)
    • AIStor — MinIO's commercial object storage product, sold as Free and Enterprise editions after the community edition was archived. (Ch 47)
    • All Software Included — Pure Storage's original licensing model in which every Purity software feature came with the array at no extra charge. (Ch 25)
    • Alletra Storage MP — HPE's common storage hardware platform that runs B10000 block and X10000 object/file software. (Ch 46)
    • Alletra Storage MP X10000 — HPE's disaggregated object store with native NFS, aimed at AI data and KV-cache offload. (Ch 46)
    • ALUA (Asymmetric Logical Unit Access) — The SCSI standard by which an array tells hosts which paths to a volume are optimized, non-optimized, standby or unavailable. (Ch 14)
    • ANA (Asymmetric Namespace Access) — NVMe's multipathing mechanism that reports which paths to a namespace are optimized, the counterpart of SCSI ALUA. (Ch 7)
    • ANN (approximate nearest neighbour) search — Similarity search that trades a small loss of recall for orders-of-magnitude speed-ups over scanning every vector. (Ch 33)
    • Antitrust remedy — A divestiture or behavioural commitment that regulators require before clearing a deal. (Ch 54)
    • Anvil — Hammerspace's metadata server that holds the global namespace and hands out pNFS layouts. (Ch 47)
    • Apache Iceberg — An open table format that adds snapshots, atomic commits, schema evolution and time travel to collections of files in object storage. (Ch 33)
    • Apache Parquet — An open columnar file format optimised for analytic scans, storing columns in compressed pages inside large row groups. (Ch 33)
    • Approved vendor list (AVL) — A platform owner's list of qualified component suppliers that reference designs may use. (Ch 34)
    • Approved-vendor list — Board-language shorthand for NVIDIA's storage certifications, which gate entry to most GPU-cluster deals without ranking vendors. (Ch 58)
    • Architectural maximum — the largest configuration a design allows in principle, before testing and support limits. (Ch 56)
    • Architectural pendulum — The recurring swing of storage design between centralized pools, distributed nodes and disaggregated fabrics as media, network and CPU costs change. (Ch 51)
    • Architecture decision matrix — A grid rating each storage architecture against each workload, used to pick a starting design before comparing vendors. (Ch 24)
    • Architecture review — a structured walk through a system's data path, metadata, failure domains, upgrades, scale limits, performance claims and roadmap dependencies. (Ch 56)
    • Archive storage — The tier that retains rarely accessed data for years at the lowest cost per terabyte, often on tape or cloud archive classes. (Ch 1)
    • Areal density — Bits stored per unit area of a disk platter or chip, the main driver of cost per bit. (Ch 2)
    • ARR multiple — A purchase price or valuation divided by the target's annual recurring revenue. (Ch 54)
    • Array controller software — The operating environment of a storage system (e.g., Purity, ONTAP) that runs placement, RAID or erasure coding, snapshots, replication and data reduction. (Ch 13)
    • ASC 606 — The US GAAP revenue-recognition standard that times revenue to the transfer of control of goods or the delivery of services. (Ch 23, Ch 25)
    • ASC 842 — The US GAAP lease standard that puts most leases on the lessee's balance sheet and defines when a contract contains a lease. (Ch 23)
    • Asymmetric active/active — A controller arrangement in which each controller owns some volumes and forwards I/O for volumes it does not own. (Ch 14)
    • Asynchronous checkpointing — Saving training state by copying it quickly to host memory and writing it to storage in the background while training continues. (Ch 11, Ch 31)
    • Asynchronous replication — Replication that acknowledges locally and ships changes later, so recent writes can be lost. (Ch 6)
    • Atlas judgment — a label for the atlas's own synthesis of public facts, such as quadrant placements or threat rankings. (Ch 0.1)
    • Attach rate — The share of an installed customer base that buys an additional product. (Ch 28, Ch 55)
    • Augmented Memory Grid — WEKA's NeuralMesh feature that streams KV cache between GPU memory and shared flash over RDMA and GPUDirect Storage. (Ch 32)
    • Augmented Memory Grid (AMG) — WEKA's KV-cache offload tier that stores evicted attention key/value blocks on pooled NVMe and streams them back to GPUs. (Ch 43, Ch 45)
    • Azure Managed Lustre — Microsoft Azure's managed Lustre parallel file system service. (Ch 36)
    • Azure Native Qumulo — Qumulo's scale-out file service sold and billed inside Microsoft Azure. (Ch 47)
    • A³I (Accelerated, Any-scale AI) — DDN's family of EXAScaler appliances and reference designs sized for NVIDIA GPU clusters. (Ch 44)

    B¶

    • Back-end compute fabric — The InfiniBand or Ethernet network that carries GPU-to-GPU traffic between racks in an AI cluster, kept separate from storage and front-end traffic. (Ch 35)
    • Back-end fabric — The network that connects storage compute nodes to storage media, separate from the front-end network clients use. (Ch 16)
    • Back-invalidate — A CXL 3.0 mechanism that lets a memory device recall cache lines from hosts, enabling coherent multi-host sharing. (Ch 12)
    • Bandwidth per TB — The throughput a device or system can deliver per terabyte stored, which falls as hard drives grow larger. (Ch 38)
    • Baseline question — A follow-up that asks what a performance or savings claim is measured against. (Ch 57)
    • BeeGFS — A parallel file system developed by ThinkParQ, a 2014 Fraunhofer spin-off, with separate management, metadata and storage services. (Ch 17)
    • Benchmark normalisation — dividing a benchmark result by rack units, power, price or capacity so that differently sized systems can be compared. (Ch 37, Ch 50)
    • BiCS — Toshiba/Kioxia's 3D NAND architecture, announced in 2007 and now built jointly with Sandisk. (Ch 52)
    • Binding constraint — The single requirement in a deal that eliminates most options before price or performance is compared. (Ch 45)
    • Bit growth — The year-on-year increase in total NAND (or DRAM) bits supplied or demanded, the key supply-demand variable in memory markets. (Ch 52)
    • Bit share — a supplier's share of total NAND capacity shipped, as opposed to its share of revenue. (Ch 48)
    • Bits per cell — The number of bits stored in one flash cell (SLC 1, MLC 2, TLC 3, QLC 4, PLC 5), set by how many voltage states the cell must distinguish. (Ch 52)
    • Blast radius — How much data or service a single component failure can take offline or put into rebuild. (Ch 24, Ch 56)
    • Blended gross margin — A company's overall gross margin as the revenue-weighted mix of higher-margin software and lower-margin hardware. (Ch 50)
    • Block protocol — A protocol that lets a host read and write numbered fixed-size blocks on a remote device, with no notion of files. (Ch 7)
    • Block storage — Storage presented as a volume of numbered fixed-size blocks whose meaning is managed by the host's file system or database. (Ch 1)
    • Bloom filter — A compact probabilistic structure that answers "definitely not present" cheaply, used to avoid deduplication index lookups for new data. (Ch 5)
    • BlueField-4 STX — NVIDIA's 2026 modular storage reference architecture in which storage services run on BlueField-4 DPUs. (Ch 10, Ch 34, Ch 45)
    • Board language — Storage jargon restated in terms of cost, risk, speed or revenue quality for a CFO or board audience. (Ch 58)
    • Bounce buffer — A staging area in host (CPU) memory that data passes through on its way between storage or the network and GPU memory. (Ch 11)
    • Bucket — The container in an object store that holds objects and carries policy, region, billing and versioning settings. (Ch 1, Ch 9)
    • Bucket index sharding — Splitting one bucket's key index into multiple shards so that writes and LIST requests spread across servers. (Ch 18)
    • Buffer-to-buffer credits — Fibre Channel's flow-control scheme, in which a sender transmits only as many frames as the receiver has buffers for, so frames are never dropped for congestion. (Ch 7)
    • Build / buy / partner — The three ways a company can obtain a capability: develop it in-house, acquire it, or contract for it with another firm. (Ch 54)
    • Build, partner or defer — the three answers a PM can give to a product gap. (Ch 55)
    • Bulk-data hop — One network traversal that a data byte makes between the flash that stores it and the client that reads or writes it. (Ch 45)
    • Bundled scaling — The constraint that each added node brings a fixed ratio of compute, cache, capacity and network ports. (Ch 15)
    • Busy polling — Having a dedicated CPU core repeatedly check for completed I/O instead of waiting for an interrupt, trading CPU for lower, steadier latency. (Ch 43)
    • Byte-range GET — An S3 read of only a specified byte range of an object, used to parallelise large reads. (Ch 9)
    • Bε-tree (B-epsilon tree) — A write-optimised B-tree whose internal nodes buffer pending updates and push them down in batches, turning small random writes into large sequential ones. (Ch 44)

    C¶

    • Cached disk array — A storage array that fronts many commodity disks with a large RAM cache so most I/O never waits for a disk (EMC Symmetrix, 1990). (Ch 51)
    • CAP theorem — The result that during a network partition a distributed system must give up either consistency or availability. (Ch 20)
    • Capability heatmap — A vendor-by-capability table using filled, half-filled and empty marks to show how fully each vendor offers each capability. (Ch 49)
    • Capacity buffer — Spare capacity a storage-as-a-service vendor guarantees to keep installed above the customer's current use (25% for Evergreen//One). (Ch 28)
    • Capex discipline — a memory maker's restraint in adding wafer capacity, used to keep supply tight and prices firm. (Ch 48)
    • Capex purchase — Buying storage outright as a capital asset that the customer owns, depreciates and eventually replaces. (Ch 23)
    • Capsule — An NVMe-oF message carrying a command or a response, and optionally in-line data. (Ch 7)
    • Catch-up launch — An incumbent product built to close an architectural gap that challengers opened first. (Ch 41)
    • Causal consistency — A guarantee that no reader sees a write without also seeing the earlier writes it depends on. (Ch 20)
    • CBox — VAST's server chassis containing multiple CNodes. (Ch 16)
    • Ceph RGW — The RADOS Gateway, Ceph's S3-compatible object interface. (Ch 47)
    • CephFS — Ceph's POSIX file system interface. (Ch 47)
    • Ceres — VAST's 2022 storage-enclosure (DBox) design that uses NVIDIA BlueField DPUs as its fabric endpoints. (Ch 42)
    • Chain replication — A replication scheme in which writes flow along an ordered chain of servers (primary to replica) and are acknowledged once the chain has persisted them. (Ch 19)
    • Charge-trap cell — The 3D NAND cell design that stores electrons in a silicon-nitride layer around a vertical channel instead of in a floating gate. (Ch 2)
    • Checkpoint — A periodic snapshot of model weights and optimizer state written during training so a job can restart after a failure. (Ch 30, Ch 31)
    • Checkpoint drain — The background transfer of a checkpoint from host memory or local NVMe to durable shared storage. (Ch 31)
    • Chunk (object store) — A large fixed-size container (128 MB in Dell ObjectScale) into which many objects are packed before erasure coding. (Ch 18)
    • Chunk Store — Tectonic's flat storage layer that holds data chunks on storage nodes. (Ch 36)
    • Chunking — Splitting documents into small passages (typically a few hundred tokens) before embedding them for retrieval. (Ch 33)
    • Clean team — A ring-fenced group allowed to review competitively sensitive material, such as source code, during a deal. (Ch 50)
    • Client eviction — A server's forced removal of an unresponsive client's locks and state, which can lose that client's cached writes. (Ch 17)
    • Client-side NFS multipath — A modified NFS client (for example VAST's) that spreads one mount across many local NICs and many server addresses. (Ch 8)
    • Clone — A writable snapshot that shares unchanged blocks with its source. (Ch 6)
    • Close-to-open consistency — The NFS guarantee that one client's writes become visible to another client only after the writer closes the file and the reader reopens it. (Ch 8)
    • Closed division — the MLPerf category with fixed benchmark code and few tunables, intended for like-for-like comparison. (Ch 37)
    • Cloud block storage — Hyperscaler-run network block volumes, such as AWS EBS, attached to cloud instances. (Ch 24, Ch 60)
    • Cluster map — The authoritative record of a cluster's membership, health and placement rules, versioned by epoch. (Ch 15)
    • ClusterMAX — SemiAnalysis's rating system for GPU clouds, scoring providers on ten criteria including storage. (Ch 35)
    • CMR / ePMR — Conventional (non-overlapping) perpendicular magnetic recording, including energy-assisted variants, the mainstream HDD technology before HAMR. (Ch 2)
    • CMX — NVIDIA's rack-scale context-memory storage platform for KV cache, the first implementation of STX. (Ch 10, Ch 34, Ch 43, Ch 53)
    • CMX (context memory storage) — NVIDIA's BlueField-4-based, Ethernet-attached flash tier for KV cache at pod level, labelled "G3.5". (Ch 32)
    • CNode — VAST's stateless compute node that runs protocols, data reduction and erasure coding but holds no authoritative state. (Ch 16)
    • CNode-X — A VAST compute node with NVIDIA GPUs, announced in February 2026, for GPU-accelerated vector search and SQL inside the storage cluster. (Ch 42)
    • Co-packaged optics (CPO) — Optical engines packaged next to a switch or processor die instead of in pluggable modules, cutting power and laser count. (Ch 53)
    • Colossus — Google's cluster-level distributed file system and the successor to GFS, underpinning Cloud Storage, YouTube and Gmail. (Ch 36)
    • Command set vs. transport — The split between what a storage protocol says (SCSI or NVMe commands) and how it travels (PCIe, FC, RDMA or TCP). (Ch 60)
    • Committed ARR — A private company's own measure of contracted annual recurring revenue (used by VAST); not an audited figure. (Ch 58)
    • Committed ARR (CARR) — The annualised value of signed recurring contracts, including those not yet live, so it runs ahead of ARR. (Ch 41, Ch 42)
    • Commoditisation risk — The danger that a software layer above the arrays (for example a global namespace) makes storage hardware interchangeable. (Ch 58)
    • Community fork — An independently maintained copy of an open-source project created when the original owner stops maintaining or restricts it. (Ch 47)
    • Compaction — Background rewriting of many small data files into fewer large ones to keep table queries fast. (Ch 33)
    • Company-stated — a label for a private company's own unaudited figure. (Ch 0.1)
    • Competitive matrix — A chart or grid placing vendors on chosen dimensions so their relative positions can be compared at a glance. (Ch 49)
    • Computational storage — Placing processing in or beside a storage device to operate on data before it crosses the host interface. (Ch 12)
    • Conditional write — A PUT that succeeds only if a precondition holds (the key is absent or its ETag matches), giving optimistic concurrency control. (Ch 9)
    • Configuration master — A separate service that records which servers form each replication chain and changes membership after failures. (Ch 19)
    • Confused deputy — A security flaw in which a privileged service is tricked into using its authority for a caller who lacks it. (Ch 39)
    • Consensus — A protocol by which a group of machines agrees on one ordered log of operations despite crashes and lost messages. (Ch 20)
    • Consistency model — The contract that defines which version of data a reader may see when copies of it disagree. (Ch 20)
    • Consistent hashing — A placement scheme that maps keys and nodes onto a ring so that adding or removing a node moves only about 1/N of the data. (Ch 15)
    • Content-aware storage — IBM's Storage Scale capability that embeds and indexes data inside the file system for retrieval-augmented AI. (Ch 46)
    • Content-defined chunking (CDC) — Cutting data where a rolling hash over the content matches a pattern, so chunk boundaries survive insertions. (Ch 5)
    • Content-derived metadata — Metadata produced by reading and classifying the content itself, such as "contains PII" or "EU customer record". (Ch 39)
    • Context memory — A storage tier that holds inference KV cache between GPU memory and shared storage so that long conversations need not be recomputed. (Ch 53)
    • Contract price — the negotiated quarterly or monthly price that large buyers pay NAND or DRAM makers, as distinct from the more volatile spot price. (Ch 48, Ch 52)
    • Control plane — The part of a storage system that holds desired state (volumes, policies, placement) and configures the data plane, operating in seconds rather than microseconds. (Ch 22)
    • Control point — the layer of the stack that owns the customer relationship and the metadata, and so captures most of the value. (Ch 0.2)
    • Controller VM (CVM) — Nutanix's per-node virtual machine that runs the storage service in an HCI cluster. (Ch 19)
    • Converged mode — A deployment in which storage software runs on the same servers as the applications or GPUs, using their local drives. (Ch 43)
    • Conversation playbook — the section of every chapter with questions for PMs and engineers, strong-answer sketches and misconceptions to avoid. (Ch 0.1)
    • Coordinator node — The cluster node a client connects to, which computes data placement and fans reads and writes out to peer nodes. (Ch 15)
    • Copy-on-write (COW) snapshot — Snapshot method that copies an old block to a reserve area before overwriting it in place. (Ch 6)
    • Copyleft — Licence terms, as in GPL and AGPL, that require derived works to be distributed under the same terms with source available. (Ch 50)
    • Copyset — A fixed group of nodes that together hold all replicas of some chunks; limiting copysets makes data loss events rarer. (Ch 20)
    • Correlated failure — Multiple failures with a shared cause (batch, firmware, power, software upgrade) that strike together and break independence assumptions. (Ch 20, Ch 56)
    • Credibility ladder — the progression from L1 to L3 knowledge that sets how far an expert will engage with you. (Ch 0.1, Ch 56)
    • CRUSH — Ceph's placement algorithm, which computes the drives for each placement group from a hierarchical cluster map and failure-domain rules, without a lookup table. (Ch 15)
    • CSI (Container Storage Interface) — The standard plug-in interface through which Kubernetes asks a storage system to create, attach and delete volumes. (Ch 22)
    • cuFile — The programming interface for GPUDirect Storage that applications call instead of POSIX read and write to move file data into or out of GPU memory. (Ch 11)
    • Cumulative bookings — The total value of all contracts a company has ever signed, including multi-year commitments not yet recognised as revenue. (Ch 42)
    • cuObject — NVIDIA's client and server libraries implementing RDMA for S3-compatible object storage. (Ch 9, Ch 11)
    • Curator — A Colossus metadata server; curators store file-system metadata in Bigtable and scale horizontally. (Ch 36)
    • Custodian — A Colossus background service that rebuilds lost data and balances disk usage. (Ch 36)
    • Customer concentration — The share of a vendor's revenue that comes from its largest customers. (Ch 50)
    • CXL (Compute Express Link) — An open interconnect that runs cache-coherent memory and I/O protocols over the PCIe physical layer. (Ch 12)
    • CXL memory — DRAM attached over a Compute Express Link (PCIe-based) connection, adding capacity at roughly two to three times local DRAM latency. (Ch 2)
    • CXL Type 3 device — A CXL memory expander: a controller plus DRAM that the host reaches with ordinary loads and stores. (Ch 12)
    • CXL.mem — The CXL protocol that lets a host read and write a device's memory at cache-line granularity. (Ch 12)

    D¶

    • D file server — Colossus's simple network-attached disk server, read and written directly by the client library. (Ch 36)
    • 3D NAND deck — One separately etched section of a tall 3D NAND layer stack; high-layer parts stack two or three decks. (Ch 2)
    • 3D XPoint — The phase-change-based persistent memory technology behind Intel Optane, co-developed with Micron. (Ch 12)
    • Dark site — A customer installation that does not phone home, typically for security reasons, and therefore forgoes cloud analytics. (Ch 22)
    • DAS (direct-attached storage) — Storage inside or cabled directly to one server, with no storage network in between. (Ch 13)
    • DASD (direct-access storage device) — IBM's term for mainframe disk storage, as opposed to sequential tape. (Ch 51)
    • DASE (disaggregated shared-everything) — A storage architecture in which stateless compute nodes share access to all media in separate enclosures over an NVMe-oF fabric, so no node owns any data. (Ch 16)
    • Data catalog — An inventory of an organisation's datasets recording their schema, owner, classification and lineage. (Ch 39)
    • Data catalog (table catalog) — The service that maps table names to their current metadata pointer and enforces access, such as Unity Catalog or Apache Polaris. (Ch 33)
    • Data curation — Filtering, deduplicating, cleaning and tokenizing raw data into a training-ready dataset. (Ch 30)
    • Data gravity — The tendency of applications, services and spending to move toward where large volumes of data already sit. (Ch 30)
    • Data lake — A low-cost, usually object-based store that holds raw and curated data for analytics and AI. (Ch 30)
    • Data lifecycle — The progression of data from creation through active use, protection, cooling and archiving to deletion. (Ch 1)
    • Data lineage — The record of where data came from, how it was transformed and which outputs or decisions it fed. (Ch 39)
    • Data loader — The training-framework component that reads, decodes and prefetches batches of samples from storage for the GPUs. (Ch 30)
    • Data node (EXA) — a third-party Linux/NVMe server running Purity//DN that stores FlashBlade//EXA file data and serves it directly to clients. (Ch 27)
    • Data orchestration — Policy-driven movement of files between tiers, sites and clouds without changing how applications address them. (Ch 47)
    • Data plane — The I/O path of a storage system that actually moves and protects bytes, which must keep running even if management services are unreachable. (Ch 22)
    • Data Primacy — Everpure's 2026 strategic framing that puts trusted, classified data rather than applications at the centre of the infrastructure stack. (Ch 28)
    • Data reduction guarantee — A vendor contract promising a minimum reduction ratio or effective capacity, usually on reducible data only, with extra capacity as the remedy. (Ch 5)
    • Data retention — How long NAND holds data without power before charge leakage causes errors; it shrinks as cells wear and as temperature rises. (Ch 2)
    • Data security posture management (DSPM) — Software that discovers and classifies sensitive data across an estate and flags where it is exposed or over-permissioned. (Ch 39)
    • Data services — The "intelligence" of a storage system: data placement, protection, data reduction and metadata management. (Ch 13)

    • Re-mirroring storm — A cascade in which many volumes lose replicas at once and their simultaneous repair traffic exhausts capacity and network. (Ch 19)

    • Read-after-write consistency — A guarantee that once a write succeeds, every subsequent read returns the new data. (Ch 9)
    • Read-modify-write penalty — The extra NAND work when a write is smaller than the drive's indirection unit, forcing the whole unit to be read, merged and rewritten. (Ch 3)
    • Real option — A small, early investment that preserves the right to scale up if a trend breaks favorably. (Ch 53)
    • Rebalancing — Background movement of data to restore even placement after nodes are added or removed. (Ch 15)
    • Rebuild storm — The burst of east-west network and drive traffic generated while a cluster restores redundancy after a drive or node failure. (Ch 15)
    • Rebuild window — Time between a drive failure and restored full redundancy, during which further failures risk data loss. (Ch 6)
    • Recall — The share of the true nearest neighbours that an approximate search actually returns. (Ch 33)
    • Recompute-versus-fetch break-even — The per-GPU bandwidth above which loading stored KV is faster than recomputing it with prefill (roughly 2–5 GB/s for a 70B model). (Ch 32)
    • Redirect-on-write (ROW) snapshot — Snapshot method that freezes the pointer map and writes new data to free space. (Ch 6)
    • Reducible data — Data not already compressed or encrypted by the host, which is what most reduction guarantees cover. (Ch 5)
    • Reference-design status — Being named in a platform vendor's validated architecture, which works as a procurement shortlist for buyers. (Ch 41)
    • Remaining performance obligations (RPO) — contracted revenue not yet recognised, including undelivered product and subscription terms. (Ch 55, Ch 58)
    • Reported by press — a label for a figure published by journalists, often from unnamed sources. (Ch 0.1)
    • Reranker — A second, more accurate model that rescores the top candidates from a vector search before they go into the prompt. (Ch 33)
    • Restore storm — The burst of simultaneous reads and metadata operations when every GPU in a job loads the latest checkpoint after a failure. (Ch 31)
    • Retimer — An active chip that recovers and re-transmits a high-speed serial signal to extend link reach. (Ch 12)
    • Revenue inflation — revenue growth driven by higher selling prices rather than more units shipped. (Ch 48)
    • Right-Size Guarantee — Everpure's (originally Pure Storage's, 2016) workload-based guarantee of effective capacity for FlashArray purchases. (Ch 5)
    • RNIC — A network interface card that implements the RDMA transport in hardware. (Ch 10)
    • RoCEv2 — RDMA over Converged Ethernet version 2: the InfiniBand transport carried in routable UDP/IP packets on Ethernet. (Ch 10)
    • Rolling hash — A hash recomputed cheaply as a window slides one byte at a time, used to find content-defined chunk boundaries (e.g., Rabin, Gear). (Ch 5)
    • Royalty / licence revenue — Fees paid to an IP owner per unit deployed, with the customer buying the underlying hardware. (Ch 29)
    • RPO (recovery point objective) — The maximum amount of recent data, measured in time, an organisation can afford to lose. (Ch 6)

    • VMware Cloud Foundation (VCF) — Broadcom's main VMware subscription bundle, licensed per core, combining vSphere, vSAN, NSX and management tools. (Ch 19)
    • Volume manager — Host or hypervisor software that pools and remaps block addresses across devices, such as LVM or software RAID. (Ch 13)
    • vSAN — VMware's HCI storage software, which runs inside the ESXi hypervisor kernel and pools node-local drives. (Ch 19)
    • vSAN Max — A VMware deployment model that builds a storage-only vSAN cluster mounted by separate compute clusters. (Ch 19)
    • VSP One — Hitachi Vantara's storage brand covering block, file and object systems. (Ch 46)

    W¶

    • Wafer bonding (NAND) — Building the NAND's CMOS control logic on a separate wafer and bonding it to the memory array wafer. (Ch 2)
    • Wafer spot price — The open-market price for unpackaged NAND wafers, quoted per die-equivalent (e.g., per 512Gb unit), a fast-moving indicator of NAND pricing. (Ch 52)
    • Wafer starts — The number of wafers a fab begins processing per month, the physical measure of memory capacity. (Ch 52)
    • Wear levelling — FTL logic that spreads program/erase cycles evenly across blocks so no part of the flash wears out early. (Ch 3)
    • WebDataset — A data-loading format and library that packs training samples into large tar shards so they can be read sequentially. (Ch 21)
    • WekaFS — WEKA's original parallel, POSIX-compliant file system for NVMe flash with tiering to object storage. (Ch 43)
    • WEKApod — WEKA's branded storage appliance line; WEKApod 3 (2026) offers Nitro, Prime and Prime Max configurations. (Ch 43)
    • Whamcloud — The Lustre engineering company bought by Intel in 2012 and revived as a DDN division after DDN bought Intel's Lustre business in 2018. (Ch 44)
    • Whiteboard prompt — a request to sketch a mechanism, such as a write path, to test L2 understanding. (Ch 56)
    • Win/loss review — a structured analysis of why specific deals were won or lost, and on which attribute. (Ch 55)
    • Witness — A data-less third voter, placed outside both sites' failure domains, that breaks ties in a two-site cluster. (Ch 20)
    • Worked example — arithmetic on stated assumptions, shown on the page so it can be checked. (Ch 0.1)
    • Workload fit — How naturally an architecture's design matches a workload's access pattern, protocol, latency and scale needs. (Ch 24)
    • Write amplification factor (WAF) — The ratio of bytes written to NAND to bytes written by the host, driven mainly by garbage collection. (Ch 3, Ch 12)
    • Write buffer — A small persistent tier that absorbs and acknowledges writes before they are reorganized and written to capacity media. (Ch 16)
    • Write quorum — The minimum number of fragment or replica writes that must succeed before a write is treated as durable. (Ch 18)
    • Write-back cache — A cache that acknowledges writes before the slower tier persists them, safe only if the cache is persistent and mirrored. (Ch 20)
    • Write-through cache — A cache that acknowledges writes only after the slower tier has persisted them. (Ch 20)

    Y¶

    • Young's formula — The classic approximation for the optimal checkpoint interval, the square root of two times the checkpoint cost times the mean time between failures. (Ch 31)

    Z¶

    • Zero-copy — Transferring data between memory and the wire without the CPU copying it between buffers. (Ch 10)
    • ZippyDB — Meta's sharded, replicated key-value store, used by Tectonic to hold its layered metadata. (Ch 36)
    • Zoned Namespaces (ZNS) — An NVMe command set that exposes zones which must be written sequentially and reset by the host. (Ch 12)
    • Zoning — A Fibre Channel switch-level access-control list defining which hosts can see which storage ports. (Ch 7)
