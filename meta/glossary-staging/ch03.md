- **SSD controller** — The embedded system-on-chip inside an SSD, with processor cores, error-correction engines and flash channel interfaces, that runs the drive's firmware. | 3
- **Flash translation layer (FTL)** — SSD firmware that maps logical block addresses to physical NAND pages, so erase-before-write flash looks like a rewritable disk. | 3
- **Logical-to-physical (L2P) table** — The FTL's map from each logical address to its current physical NAND location, usually held in on-drive DRAM. | 3
- **Indirection unit (IU)** — The granularity at which an SSD's mapping table tracks data; larger units save DRAM but penalise smaller writes. | 3
- **Garbage collection (GC)** — Background work that copies valid pages out of partly stale blocks so the blocks can be erased and reused. | 3
- **Write amplification factor (WAF)** — The ratio of bytes written to NAND to bytes written by the host, driven mainly by garbage collection. | 3
- **Over-provisioning (OP)** — Flash installed in a drive but hidden from the host, used as working space for garbage collection, expressed as a percentage of user capacity. | 3
- **TRIM / Deallocate** — A host command telling the drive that logical blocks no longer hold useful data, so garbage collection can skip them. | 3
- **Wear levelling** — FTL logic that spreads program/erase cycles evenly across blocks so no part of the flash wears out early. | 3
- **LDPC (low-density parity-check) code** — The strong error-correcting code that modern SSD controllers apply to every NAND read. | 3
- **Read retry** — Re-reading a NAND page at shifted reference voltages when error correction fails, at the cost of extra latency. | 3
- **Power-loss protection (PLP)** — On-drive capacitors that hold up power long enough to flush buffered writes and map updates after a power failure. | 3
- **Host Memory Buffer (HMB)** — An NVMe feature that lets a DRAM-less SSD borrow a slice of host memory to cache its mapping table. | 3
- **Read-modify-write penalty** — The extra NAND work when a write is smaller than the drive's indirection unit, forcing the whole unit to be read, merged and rewritten. | 3
- **Log-on-log** — Stacking a log-structured array on top of SSDs that are themselves log-structured, duplicating garbage collection, spare space and mapping. | 3
- **Greedy garbage collection** — A GC policy that always reclaims the block with the fewest valid pages, minimising copies under random writes. | 3
