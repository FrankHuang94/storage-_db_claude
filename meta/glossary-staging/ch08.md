- **NFS (Network File System)** — The standard file-sharing protocol on Linux and Unix, in which clients send file-level operations to a server that owns the file system. | 8
- **NFSv3** — The stateless 1995 version of NFS (RFC 1813), still the most widely deployed, with locking handled by separate side protocols. | 8
- **NFSv4.1** — The NFS minor version (RFC 5661, now RFC 8881) that added sessions, trunking and parallel NFS (pNFS). | 8
- **NFSv4.2** — The NFS minor version (RFC 7862, 2016) that added server-side copy, sparse files, I/O hints and labeled NFS. | 8
- **File handle** — An opaque token issued by an NFS server that identifies a file in every subsequent request. | 8
- **Close-to-open consistency** — The NFS guarantee that one client's writes become visible to another client only after the writer closes the file and the reader reopens it. | 8
- **Delegation** — An NFSv4 grant that lets one client cache a file exclusively until the server recalls it. | 8
- **Lease** — A time-bounded grant of state (opens, locks) that an NFSv4 client must keep renewing or lose. | 8
- **pNFS (parallel NFS)** — An NFSv4.1+ feature in which a metadata server hands clients a layout so they can read and write data servers directly and in parallel. | 8
- **Layout** — The pNFS map telling a client which data servers hold which byte ranges of a file and how they are striped. | 8
- **Flex Files layout** — The pNFS layout type (RFC 8435, 2018) whose data servers can be ordinary NFSv3 servers and which supports client-side mirroring. | 8
- **Single-head bottleneck** — The limit reached when every byte of a NAS mount must pass through one server controller's CPU, memory and NICs. | 8
- **nconnect** — A Linux NFS mount option (kernel 5.3+) that opens up to 16 TCP connections per mount to the same server. | 8
- **NFS over RDMA** — NFS carried over RPC-over-RDMA (RFC 8166/8267), letting servers place data directly in client memory with little CPU involvement. | 8
- **Client-side NFS multipath** — A modified NFS client (for example VAST's) that spreads one mount across many local NICs and many server addresses. | 8
- **SMB3** — The Windows file-sharing protocol version introduced with Windows Server 2012, adding Multichannel, SMB Direct and transparent failover. | 8
- **SMB Multichannel** — An SMB3 feature that automatically spreads one session over several network connections and adapters. | 8
- **SMB Direct** — SMB3 running over RDMA (iWARP, InfiniBand or RoCE) for low-latency, low-CPU file access. | 8
- **POSIX semantics** — The Unix file-system behaviour (open, read, write, rename, byte-range locks, immediate visibility) that applications assume of a local disk. | 8
