- **Object** — An immutable blob of bytes plus metadata, stored and retrieved whole by key through an API such as S3. | 9
- **Bucket** — The container in an object store that holds objects and carries policy, region, billing and versioning settings. | 9
- **Object key** — The string name that addresses an object in a bucket's flat namespace; slashes in it are just characters. | 9
- **Flat namespace** — An addressing scheme with no real directories, where "folders" are only shared key prefixes. | 9
- **S3 (Simple Storage Service) API** — Amazon's HTTP/REST interface for object storage, now the de facto standard implemented by most storage vendors. | 9
- **SigV4** — AWS Signature Version 4, which signs each HTTP request with an HMAC-derived key so the server can authenticate it without the secret crossing the wire. | 9
- **ETag** — An identifier of an object's content or version, returned on writes and used for integrity checks and conditional requests. | 9
- **Multipart upload** — An S3 method for uploading a large object as many parallel, independently retryable parts that become visible atomically on completion. | 9
- **Byte-range GET** — An S3 read of only a specified byte range of an object, used to parallelise large reads. | 9
- **Partitioned prefix** — The key-prefix unit by which S3 scales request throughput, each supporting at least 3,500 writes and 5,500 reads per second. | 9
- **Conditional write** — A PUT that succeeds only if a precondition holds (the key is absent or its ETag matches), giving optimistic concurrency control. | 9
- **Read-after-write consistency** — A guarantee that once a write succeeds, every subsequent read returns the new data. | 9
- **S3 Express One Zone** — An AWS S3 storage class using single-Availability-Zone directory buckets for single-digit-millisecond access. | 9
- **S3 Tables** — AWS table buckets that store and automatically maintain Apache Iceberg tables inside S3. | 9
- **S3 Vectors** — An AWS S3 capability that stores and queries vector embeddings natively in vector buckets. | 9
- **S3 over RDMA** — A data path in which a normal S3 request carries a memory token over HTTP while the object bytes move by RDMA directly to or from host or GPU memory. | 9
- **cuObject** — NVIDIA's client and server libraries implementing RDMA for S3-compatible object storage. | 9
- **Small-object tax** — The disproportionate request cost and rate-limit pressure incurred when data is stored as many small objects. | 9
