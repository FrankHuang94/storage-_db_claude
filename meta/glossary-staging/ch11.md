- **Bounce buffer** — A staging area in host (CPU) memory that data passes through on its way between storage or the network and GPU memory. | 11
- **GPUDirect RDMA** — NVIDIA technology that lets a network card read or write GPU memory directly over PCIe, without copying through host memory. | 11
- **GPUDirect Storage (GDS)** — NVIDIA technology that lets storage data move by direct DMA between a NIC or NVMe SSD and GPU memory, bypassing the CPU bounce buffer. | 11
- **cuFile** — The programming interface for GPUDirect Storage that applications call instead of POSIX read and write to move file data into or out of GPU memory. | 11
- **GDS compatibility mode** — The fallback in which cuFile calls still work but data passes through a host-memory bounce buffer because the platform or file system does not support the direct path. | 11
- **Magnum IO** — NVIDIA's umbrella name for its GPU input/output software, including GPUDirect RDMA, GPUDirect Storage, NCCL, NVSHMEM and UCX. | 11
- **NCCL** — NVIDIA's library for collective communication (such as all-reduce) between GPUs within and across servers. | 11
- **NIXL (NVIDIA Inference Xfer Library)** — An open-source library that moves KV-cache blocks and tensors between GPU memory, CPU memory and storage through pluggable backends. | 11
- **NVIDIA Dynamo** — NVIDIA's open-source distributed inference-serving framework that routes requests and manages KV cache across GPUs and memory tiers. | 11
- **KVBM (KV Block Manager)** — The Dynamo component that tiers KV-cache blocks across GPU memory, host DRAM, local SSD and remote storage. | 11
- **cuObject** — NVIDIA libraries that move S3 object data directly into GPU or system memory over RDMA while keeping S3 requests for control. | 11
- **S3 over RDMA** — A way of serving S3 object reads and writes in which the data payload travels over RDMA instead of TCP. | 11
- **Peer-to-peer DMA** — A transfer in which one PCIe device (such as a NIC) writes directly into another device's memory (such as a GPU) without involving host memory. | 11
- **Effective training time** — The share of elapsed time that a training job spends doing useful training, after interruptions, restarts and checkpoint pauses. | 11
- **Asynchronous checkpointing** — Saving training state by copying it quickly to host memory and writing it to storage in the background while training continues. | 11
- **Data stall** — Time a GPU waits for training data to be fetched from storage or pre-processed. | 11
