- **Dual-controller array** — A scale-up storage system in which two controllers share dual-ported drives and each can take over the other's work if it fails. | 14
- **Scale-up** — Growing a storage system by adding drives or faster controllers behind a fixed controller pair rather than adding nodes. | 14
- **NVRAM write log** — A small battery-, capacitor- or flash-backed persistent buffer that holds acknowledged writes until they are flushed to flash. | 14
- **Mirrored write cache** — A design in which each write is copied to the partner controller's persistent memory before the host is acknowledged. | 14
- **HA interconnect** — The dedicated link between two controllers that carries heartbeats and mirrored write data. | 14
- **Stateless controller** — A controller that holds no unique data or configuration, so it can be replaced without destaging or migrating anything. | 14
- **Active/passive** — A controller arrangement in which one controller serves all I/O while the other waits to take over. | 14
- **Asymmetric active/active** — A controller arrangement in which each controller owns some volumes and forwards I/O for volumes it does not own. | 14
- **Symmetric active/active** — A controller arrangement in which every path is optimized and any controller can serve any volume. | 14
- **ALUA (Asymmetric Logical Unit Access)** — The SCSI standard by which an array tells hosts which paths to a volume are optimized, non-optimized, standby or unavailable. | 14
- **Active/optimized path** — A path the array advertises as the preferred, lowest-latency route to a volume. | 14
- **Active/non-optimized path** — A working path that costs an extra internal hop and is used only when optimized paths fail. | 14
- **Multipath I/O (MPIO)** — Host software that spreads I/O over several paths to an array and fails over between them. | 14
- **Takeover / giveback** — A partner controller assuming a failed or upgrading controller's volumes, then returning them when it rejoins. | 14
- **Non-disruptive upgrade (NDU)** — Upgrading array software or controller hardware one controller at a time so hosts keep running. | 14
- **Data-in-place upgrade** — A controller hardware upgrade that leaves drives, data and configuration in place, so no migration is needed. | 14
- **Federation** — Managing several arrays or controller pairs as one cluster with volume mobility, without merging them into one system. | 14
- **Headroom tax** — The capacity a redundant pair leaves unused so a single surviving controller can carry the full load. | 14
- **Purity Turbo** — An Everpure feature for FlashArray//XL190 that lets the secondary controller serve read I/O. | 14
- **DFMD** — An Everpure DirectFlash module with built-in NVRAM, so write-log capacity grows with the number of modules. | 14
