- **Shared-nothing cluster** — A storage architecture in which each node owns its own CPUs, memory and drives, and nodes cooperate only by sending requests over the network. | 15
- **Scale-out** — Growing a storage system by adding whole nodes rather than upgrading a controller pair. | 15
- **Coordinator node** — The cluster node a client connects to, which computes data placement and fans reads and writes out to peer nodes. | 15
- **Front-end network** — The network that carries traffic between clients and storage nodes (north-south). | 15
- **East-west traffic** — Traffic between storage nodes, such as replicas, erasure-coded fragments, forwarded reads, rebalancing and rebuilds. | 15
- **Consistent hashing** — A placement scheme that maps keys and nodes onto a ring so that adding or removing a node moves only about 1/N of the data. | 15
- **Virtual nodes** — Many points on a consistent-hashing ring assigned to each physical server to even out load. | 15
- **CRUSH** — Ceph's placement algorithm, which computes the drives for each placement group from a hierarchical cluster map and failure-domain rules, without a lookup table. | 15
- **Placement group (PG)** — Ceph's unit of placement and rebalancing, grouping many objects that are mapped together to the same set of drives. | 15
- **OSD (object storage daemon)** — The Ceph process that manages one drive and stores, replicates and recovers its objects. | 15
- **Primary OSD** — The OSD that receives a placement group's writes, forwards them to replicas and acknowledges the client. | 15
- **Cluster map** — The authoritative record of a cluster's membership, health and placement rules, versioned by epoch. | 15
- **Quorum** — The majority of voting members (e.g., 3 of 5 monitors) required to change cluster state, which prevents split brain. | 15
- **Split brain** — A network partition in which two sides of a cluster each act as if they were the whole cluster, risking conflicting writes. | 15
- **Rebalancing** — Background movement of data to restore even placement after nodes are added or removed. | 15
- **Rebuild storm** — The burst of east-west network and drive traffic generated while a cluster restores redundancy after a drive or node failure. | 15
- **Grace timer** — The wait before a missing node is declared failed, so a brief reboot triggers only a resync instead of a full rebuild. | 15
- **Protection level (OneFS)** — PowerScale's notation for how many drive or node failures a file can survive, e.g., +2d:1n. | 15
- **Bundled scaling** — The constraint that each added node brings a fixed ratio of compute, cache, capacity and network ports. | 15
