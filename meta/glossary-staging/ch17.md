- **Parallel file system** — A file system in which clients get a file's layout from metadata servers and then read and write its data directly and in parallel across many storage servers. | 17
- **Lustre** — The open-source parallel file system that runs most of the world's largest supercomputers, now developed mainly by DDN's Whamcloud unit and the community. | 17
- **MGS (management server)** — The Lustre server that stores cluster configuration, which clients read when they mount the file system. | 17
- **MDS (metadata server)** — The server in a parallel file system that handles namespace operations and hands out file layouts and locks. | 17
- **MDT (metadata target)** — The storage volume behind a Lustre MDS that holds directories, inodes, permissions and file layouts. | 17
- **OSS (object storage server)** — The Lustre server that serves file data from its object storage targets. | 17
- **OST (object storage target)** — A Lustre data volume, usually a RAID-protected local file system, that stores file data as objects. | 17
- **LNet** — Lustre's network layer, which carries traffic over RDMA fabrics such as InfiniBand and RoCE or over TCP and can route between them. | 17
- **File layout** — The map that tells a client which storage targets hold which parts of a file, including stripe size and stripe count. | 17
- **Stripe size** — The size of each chunk a file is cut into before the chunks are spread across storage targets. | 17
- **Stripe count** — The number of storage targets a file's chunks are dealt across, which sets its maximum parallel bandwidth. | 17
- **Progressive File Layout (PFL)** — A Lustre feature that widens a file's stripe count automatically as the file grows. | 17
- **DNE (Distributed Namespace)** — Lustre's mechanism for spreading the namespace across several MDTs, via remote or striped directories. | 17
- **Data-on-MDT (DoM)** — A Lustre feature that stores the first part, or all, of small files on the metadata target to avoid a round trip to a data server. | 17
- **Extent lock** — A distributed lock on a byte range of a file, letting several clients write different ranges of one file coherently. | 17
- **Client eviction** — A server's forced removal of an unresponsive client's locks and state, which can lose that client's cached writes. | 17
- **Failover pair** — Two servers attached to the same dual-ported storage so either can take over the other's targets if one fails. | 17
- **IBM Storage Scale (GPFS)** — IBM's parallel file system, shipped since 1998 and renamed from Spectrum Scale in 2022, which distributes metadata management across nodes using tokens. | 17
- **BeeGFS** — A parallel file system developed by ThinkParQ, a 2014 Fraunhofer spin-off, with separate management, metadata and storage services. | 17
- **IO500** — A twice-yearly ranking of HPC storage systems, started at SC17, that combines bandwidth and metadata scores via geometric means. | 17
