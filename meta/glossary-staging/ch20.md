- **Consistency model** — The contract that defines which version of data a reader may see when copies of it disagree. | 20
- **Linearizability (strong consistency)** — A guarantee that every read sees the latest acknowledged write, as if only one copy existed. | 20
- **Eventual consistency** — A guarantee only that all copies converge once writes stop, so reads in the meantime may be stale. | 20
- **Causal consistency** — A guarantee that no reader sees a write without also seeing the earlier writes it depends on. | 20
- **Consensus** — A protocol by which a group of machines agrees on one ordered log of operations despite crashes and lost messages. | 20
- **Paxos** — Lamport's majority-based consensus protocol, published in 1998 and used in systems such as Ceph monitors and DynamoDB. | 20
- **Raft** — A consensus protocol (2014) designed to be easy to understand, with leader election by term and majority-committed log replication. | 20
- **Term (Raft)** — Raft's logical clock; each term has at most one leader, and a node seeing a higher term steps down. | 20
- **Quorum (N/W/R)** — The replica count N and the number of write (W) and read (R) acknowledgements required; W + R > N ensures reads overlap the latest write. | 20
- **CAP theorem** — The result that during a network partition a distributed system must give up either consistency or availability. | 20
- **PACELC** — An extension of CAP: under a Partition choose Availability or Consistency, Else choose Latency or Consistency. | 20
- **Witness** — A data-less third voter, placed outside both sites' failure domains, that breaks ties in a two-site cluster. | 20
- **Pre-election** — Everpure ActiveCluster behaviour that pre-selects a surviving array per pod when both arrays lose contact with the mediator. | 20
- **MTTDL (mean time to data loss)** — A modelled estimate of how long a protection scheme runs before enough overlapping failures lose data. | 20
- **AFR (annualized failure rate)** — The fraction of devices expected to fail per year of operation. | 20
- **FIT (failures in time)** — Failures per 10^9 device-hours; a 1% AFR is about 1,140 FIT. | 20
- **Correlated failure** — Multiple failures with a shared cause (batch, firmware, power, software upgrade) that strike together and break independence assumptions. | 20
- **Failure domain** — A set of components that can fail together, such as a drive, node, enclosure, rack, power zone, site or region. | 20
- **Copyset** — A fixed group of nodes that together hold all replicas of some chunks; limiting copysets makes data loss events rarer. | 20
- **Write-back cache** — A cache that acknowledges writes before the slower tier persists them, safe only if the cache is persistent and mirrored. | 20
- **Write-through cache** — A cache that acknowledges writes only after the slower tier has persisted them. | 20
