- **Architecture decision matrix** — A grid rating each storage architecture against each workload, used to pick a starting design before comparing vendors. | 24
- **Workload fit** — How naturally an architecture's design matches a workload's access pattern, protocol, latency and scale needs. | 24
- **Latency-bound workload** — A workload whose performance depends on how quickly each small I/O completes, such as an OLTP database. | 24
- **Throughput-bound workload** — A workload whose performance depends on aggregate bytes per second across many parallel streams, such as AI training data loading. | 24
- **Blast radius** — How much data or service a single component failure can take offline or put into rebuild. | 24
- **Unified storage platform** — A system or product family that serves block, file and object from one software stack or control plane. | 24
- **Enterprise storage platform** — Gartner's category, created in 2025, covering products that serve block, file and object workloads together. | 24
- **Cloud block storage** — Hyperscaler-run network block volumes, such as AWS EBS, attached to cloud instances. | 24
- **S3 Vectors** — AWS's vector storage and query capability built into Amazon S3, generally available since December 2025. | 24
- **PureKVA** — Everpure's KV-cache offload software on FlashBlade (formerly Key Value Accelerator), serving cached LLM attention state over S3 and NFS. | 24
- **Pure Storage Cloud Dedicated** — Everpure's customer-managed Purity block service on AWS and Azure, formerly Cloud Block Store. | 24
- **Single namespace** — One file or object directory tree that all clients see, regardless of how many nodes store the data. | 24
