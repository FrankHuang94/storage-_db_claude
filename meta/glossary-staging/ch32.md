- **KV cache** — The stored attention keys and values for every token a model has already processed, kept so they need not be recomputed at each generation step. | 32
- **Prefill** — The compute-bound inference phase that processes the whole prompt in parallel and produces the KV cache. | 32
- **Decode** — The memory-bandwidth-bound inference phase that generates one token per step while rereading the weights and the full KV cache. | 32
- **Time to first token (TTFT)** — The delay between submitting a request and receiving the first output token, dominated by prefill or by KV-cache restore. | 32
- **Prefix caching** — Reusing stored KV blocks for the identical leading tokens (system prompt, document, earlier turns) shared by many requests. | 32
- **Grouped-query attention (GQA)** — An attention design in which several query heads share one key/value head, shrinking the KV cache per token. | 32
- **Multi-head latent attention (MLA)** — DeepSeek's attention design that caches a compressed latent vector per layer instead of full keys and values, cutting KV size several-fold. | 32
- **Disaggregated serving** — Running prefill and decode on separate GPU pools and transferring the KV cache between them. | 32
- **PagedAttention** — vLLM's technique of storing KV cache in fixed-size pages, like virtual memory, to cut fragmentation and enable block sharing. | 32
- **KVBM (KV Block Manager)** — The NVIDIA Dynamo component that moves KV blocks across tiers G1 (HBM), G2 (host DRAM), G3 (local SSD) and G4 (networked storage). | 32
- **NVIDIA Dynamo** — NVIDIA's open-source distributed inference-serving framework with KV-aware routing, disaggregated serving and KV tiering. | 32
- **CMX (context memory storage)** — NVIDIA's BlueField-4-based, Ethernet-attached flash tier for KV cache at pod level, labelled "G3.5". | 32
- **LMCache** — An open-source KV-cache layer that offloads and shares KV between inference engines such as vLLM and SGLang and storage tiers. | 32
- **llm-d** — An open-source, Kubernetes-native distributed inference project (CNCF Sandbox) with KV-aware scheduling and offload. | 32
- **PureKVA** — Everpure's KV-cache offering on FlashBlade (formerly Key Value Accelerator), integrated with vLLM and NVIDIA Dynamo. | 32
- **Augmented Memory Grid** — WEKA's NeuralMesh feature that streams KV cache between GPU memory and shared flash over RDMA and GPUDirect Storage. | 32
- **Recompute-versus-fetch break-even** — The per-GPU bandwidth above which loading stored KV is faster than recomputing it with prefill (roughly 2–5 GB/s for a 70B model). | 32
