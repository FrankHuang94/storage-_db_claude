- **RAG (retrieval-augmented generation)** — A pattern in which an application retrieves relevant chunks of private data and inserts them into an LLM prompt so answers are grounded in that data. | 33
- **Embedding** — A fixed-length vector of numbers produced by a model so that items with similar meaning sit close together in vector space. | 33
- **Chunking** — Splitting documents into small passages (typically a few hundred tokens) before embedding them for retrieval. | 33
- **Vector database** — Software that stores embeddings and answers nearest-neighbour similarity queries, usually with metadata filters. | 33
- **ANN (approximate nearest neighbour) search** — Similarity search that trades a small loss of recall for orders-of-magnitude speed-ups over scanning every vector. | 33
- **Recall** — The share of the true nearest neighbours that an approximate search actually returns. | 33
- **HNSW** — Hierarchical Navigable Small World, a multi-layer proximity-graph vector index that is fast in DRAM but needs one dependent memory access per hop. | 33
- **IVF (inverted file index)** — A vector index that clusters vectors and searches only the few clusters nearest the query. | 33
- **DiskANN** — Microsoft's SSD-resident graph vector index that keeps compressed codes in DRAM and the full graph and vectors on flash. | 33
- **Product quantization (PQ)** — Compressing a vector by splitting it into sub-vectors and replacing each with a small codebook index, cutting memory by tens of times. | 33
- **Reranker** — A second, more accurate model that rescores the top candidates from a vector search before they go into the prompt. | 33
- **Apache Parquet** — An open columnar file format optimised for analytic scans, storing columns in compressed pages inside large row groups. | 33
- **Lance** — An open columnar file format, created by LanceDB's founders, designed for both scans and fast random row access to embeddings and multimodal data. | 33
- **Apache Iceberg** — An open table format that adds snapshots, atomic commits, schema evolution and time travel to collections of files in object storage. | 33
- **Delta Lake** — Databricks-originated open table format that adds a transaction log to Parquet files in object storage. | 33
- **Lakehouse** — An architecture that runs warehouse-style SQL and AI workloads directly on open file and table formats in object storage. | 33
- **Data catalog (table catalog)** — The service that maps table names to their current metadata pointer and enforces access, such as Unity Catalog or Apache Polaris. | 33
- **Compaction** — Background rewriting of many small data files into fewer large ones to keep table queries fast. | 33
