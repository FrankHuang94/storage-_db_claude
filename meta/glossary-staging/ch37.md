- **MLPerf Storage** — MLCommons' benchmark that measures how well a storage system feeds AI workloads using software-simulated accelerators instead of real GPUs. | 37
- **DLIO** — the deep-learning I/O emulator MLPerf Storage uses to mimic framework data loading and to "sleep" in place of accelerator compute. | 37
- **Simulated accelerator** — a software stand-in for a GPU in MLPerf Storage that waits a calibrated time per batch instead of computing. | 37
- **Accelerator utilisation (AU)** — the share of time a simulated accelerator spends computing rather than waiting for data; MLPerf Storage results must stay above a threshold. | 37
- **Closed division** — the MLPerf category with fixed benchmark code and few tunables, intended for like-for-like comparison. | 37
- **Open division** — the MLPerf category that allows disclosed changes to loaders, formats or frameworks, so results are not directly comparable with closed ones. | 37
- **SPECstorage Solution 2020** — SPEC's file-storage benchmark with five workloads (AI_IMAGE, EDA_BLENDED, GENOMICS, SWBUILD, VDA), each scored as a business metric at an overall response time. | 37
- **Overall response time (ORT)** — SPECstorage's average latency across the load points of a run. | 37
- **IO500** — a twice-yearly HPC storage ranking that combines IOR bandwidth tests and mdtest/find metadata tests into one geometric-mean score. | 37
- **ior-easy / ior-hard** — IO500 bandwidth tests: large, well-aligned sequential I/O versus small, unaligned I/O to a shared file. | 37
- **mdtest** — the IO500 metadata test that creates, stats and deletes many files to stress a file system's metadata path. | 37
- **IO500 Production list** — the IO500 list restricted to submissions that pass a reproducibility review, separate from the Research list for experimental systems. | 37
- **STAC-M3** — an audited benchmark of kdb+ tick-data analytics used by financial-services buyers to compare storage and compute stacks. | 37
- **fio** — the standard open-source I/O load generator used for vendor and customer storage tests, whose job file defines block size, queue depth and data pattern. | 37
- **elbencho** — an open-source distributed storage benchmark tool for file, object and GPU-direct testing. | 37
- **Hero configuration** — a benchmark system sized to win a headline rather than to match a realistic purchase. | 37
- **Benchmark normalisation** — dividing a benchmark result by rack units, power, price or capacity so that differently sized systems can be compared. | 37
