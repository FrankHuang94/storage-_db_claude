### 1.2 Technology

- **DASE (Disaggregated, Shared-Everything):** stateless compute nodes (CNodes) are separated from storage enclosures (DBoxes) that hold storage-class memory (SCM) and QLC flash. Every CNode can reach every device over NVMe-oF, so any CNode can serve any request without east-west coordination traffic between nodes. — Source: VAST Data, "How it works", n.d., https://vastdata.com/how-it-works (retrieved 2026-11-01)
- Cisco's solution brief also describes the CNode/DBox split and the SCM-plus-QLC media design for VAST running on Cisco UCS. — Source: Cisco, "VAST Data on Cisco UCS (solution overview)", n.d., https://www.cisco.com/c/en/us/solutions/collateral/artificial-intelligence/vast-data-ucs-ds.pdf (retrieved 2026-11-01)
- **Element Store:** VAST's internal data structure. SCM absorbs writes and holds metadata, and data is later written to QLC in large, flash-friendly stripes. Similarity-based data reduction is part of this layer. — Source: VAST Data, "How it works", n.d., https://vastdata.com/how-it-works (retrieved 2026-11-01)
- **Similarity-based data reduction:** VAST describes it as global and byte-granular. A VAST webinar cites a median reduction of about 2:1 across real datasets, while a third-party encyclopedia entry claims about 3:1. — Source: VAST Data, "Scaling Through Flash Scarcity" (webinar), n.d., https://www.vastdata.com/events/scaling-through-flash-scarcity (retrieved 2026-11-01) [VERIFY: the reduction ratios are vendor figures and the two sources disagree]
- **Locally decodable erasure codes (LDEC):** these use wide stripes with very low overhead. VAST cites under 3% (2.7% in some materials). A rebuild reads only about a quarter of the surviving data, compared with all surviving strips for Reed-Solomon. — Source: VAST Data blog, "Beyond Better Codes (Providing Resilience Efficiently, Part II)", n.d., https://vastdata.com/blog/providing-resilience-efficiently-part-ii (retrieved 2026-11-01)
- **Multiprotocol access:** NFS (including NFS over RDMA), SMB and S3 to the same data, with block added later. Kafka-compatible event streaming also appears in AI OS materials. — Source: VAST Data, "Supported Platforms / Specifications", n.d., https://www.vastdata.com/specifications (retrieved 2026-11-01) [VERIFY: confirm the block and Kafka protocol list against current docs]
- **VAST DataBase:** a tabular/columnar database built into the platform, launched with the "VAST Data Platform" in 2023. It now underpins DataEngine and the vector search features. — Source: The Next Platform, "VAST Data: What controls the data is more important than what stores it", 2026-02-27, https://www.nextplatform.com/store/2026/02/27/vast-data-what-controls-the-data-is-more-important-than-what-stores-it/4092860 (retrieved 2026-11-01)
- **DataSpace:** a global namespace that spans sites and clouds. It was extended into a hybrid namespace for the Google Cloud managed service in November 2025. — Source: SDxCentral, "Google Cloud enlists VAST Data to support AI multi-environment deployments", 2025-11, https://www.sdxcentral.com/news/google-cloud-enlists-vast-data-to-support-ai-multi-environment-deployments/ (retrieved 2026-11-01)
- **DataEngine:** a serverless, event-triggered execution layer (functions, triggers, containers) inside the platform. — Source: Futuriom, "VAST Data Declares Itself an AI Operating System", 2025-05, https://www.futuriom.com/articles/news/vast-data-declares-itself-an-ai-operating-system/2025/05 (retrieved 2026-11-01)
- **InsightEngine:** prepares data for AI use, including real-time embedding, indexing and RAG. It was introduced in October 2024 according to HPCwire; another source says March 2025. — Source: HPCwire, "VAST Data Expands AI Data Stack, Keeps Eye on North Star", 2026-02-25, https://www.hpcwire.com/2026/02/25/vast-data-expands-ai-data-stack-keeps-eye-on-north-star/ (retrieved 2026-11-01) [VERIFY: the launch date conflicts between sources]
- **AgentEngine:** an auto-scaling runtime for deploying AI agents, with a low-code environment and support for MCP-compatible tools. It was the headline component of the May 2025 AI OS launch. — Source: Blocks & Files, "VAST Data launches AI operating system", 2025-05-21, https://www.blocksandfiles.com/ai-ml/2025/05/21/vast-data-launches-ai-operating-system/1613219 (retrieved 2026-11-01)
- **Current naming (2026):** the umbrella brand is the "VAST AI Operating System" (AI OS). Its components include DataStore, DataBase, DataSpace, DataEngine, InsightEngine, AgentEngine, SyncEngine (August 2025), and TuningEngine and PolicyEngine (announced February 2026, due by the end of 2026). A "Polaris" control plane was also mentioned. — Source: HPCwire, "VAST Data Expands AI Data Stack, Keeps Eye on North Star", 2026-02-25, https://www.hpcwire.com/2026/02/25/vast-data-expands-ai-data-stack-keeps-eye-on-north-star/ (retrieved 2026-11-01) [VERIFY: whether Polaris is a separate product name]

### 2.2 Technology

- **WekaFS:** WEKA's original parallel, POSIX-compliant file system for NVMe flash, with tiering to S3-compatible object storage (the "object tier"). — Source: WEKA docs, "WEKA networking" (v4.2 overview), n.d., https://docs.weka.io/4.2/overview/networking-in-wekaio (retrieved 2026-11-01) [VERIFY: the tiering description is background knowledge and is not covered by this doc page]
- **Kernel-bypass data path:** backend servers must run DPDK with SR-IOV, which maps the NIC into user space and bypasses kernel networking. Clients can use DPDK or kernel UDP. In "performance-optimized" mode cores are dedicated to WEKA. In "CPU-optimized" mode (5.0) DPDK uses RX interrupts and does not pin cores. UDP mode is the fallback, for example on AWS ENA in some modes. — Source: WEKA docs, "Networking in WEKA" (v5.0), n.d., https://docs.weka.io/5.0/weka-system-overview/networking-in-wekaio (retrieved 2026-11-01)
- **NeuralMesh (June 2025):** a service-oriented design in which each node runs one or more microservices (data access, metadata, auditing, observability) in a dynamically connected mesh. WEKA says it gets stronger and faster as it grows, which it contrasts with monolithic storage. — Source: WEKA press release, "WEKA Introduces NeuralMesh", 2025-06-17, https://www.weka.io/company/weka-newsroom/press-releases/weka-introduces-neuralmesh/ (retrieved 2026-11-01)
- **Augmented Memory Grid (AMG):** stores and reuses KV cache on NeuralMesh-managed NVMe to extend GPU memory. Vendor claims are 1000x memory extension, up to 20x faster time to first token and 10x more concurrent users. It integrates with NVIDIA GPUDirect Storage, Dynamo and NIXL, and WEKA open-sourced a NIXL plugin. — Source: WEKA, "WEKA Breaks The AI Memory Barrier With Augmented Memory Grid on NeuralMesh", 2025-11-18, https://www.weka.io/news/weka-breaks-the-ai-memory-barrier-with-augmented-memory-grid (retrieved 2026-11-01) [VERIFY: vendor performance claims with no independent test found]
- **NeuralMesh 6 (July 2026):** adds native multi-tenancy, data reduction, unified file and object access, and an enhanced AMG. — Source: HPCwire, "WEKA Launches NeuralMesh 6 and WEKApod as AI Inference Pushes Infrastructure Limits", 2026-07-22, https://www.hpcwire.com/2026/07/22/weka-launches-neuralmesh-6-and-wekapod-as-ai-inference-pushes-infrastructure-limits/ (retrieved 2026-11-01)
- **WEKApod:** WEKA's turnkey appliance line, with Nitro and Prime variants certified for NVIDIA DGX SuperPOD in 2025.
